## Stack

| File storage | S3-compatible object storage (AWS S3, Cloudflare R2 or MinIO), presigned URLs, private bucket | One API for every provider, files stay out of the database and off the app server |

## Project layout

```
src/storage/                   the only module that talks to the S3 client (put, get, delete, presign)
.env.example                   S3_ENDPOINT, S3_REGION, S3_BUCKET, S3_ACCESS_KEY_ID, S3_SECRET_ACCESS_KEY (no values)
```

## Conventions

- The database stores the object key, content type and size; never the file bytes and never a public URL.
- Keys are generated by the server (`<tenant>/<uuid>/<sanitized-name>`), never taken from user input as is.
- Uploads go straight from the client to the bucket with a presigned PUT/POST that expires in minutes and fixes content type and max size.
- Downloads use presigned GET URLs (or a public CDN only for assets that are public on purpose).
- Endpoint and path-style access come from configuration so MinIO in development and S3/R2 in production share the code.

## Commands

| Storage up | `docker compose up -d minio` |

## Testing

- Tests run against MinIO (or a fake client behind the `src/storage/` interface), never against the production bucket.

## Rules for agents

- Buckets are private by default; never set a public ACL or a public bucket policy.
- Never put access keys in code or in the client bundle; presign on the server.
- Validate content type, size and extension on the server before presigning, and scan or re-encode untrusted uploads.
