## Stack

| Auth | Better Auth (sessions stored in the database, email + password, OAuth, optional passkeys and 2FA) | Auth you own, in your database, with no per-user pricing |

## Project layout

```
src/lib/auth.ts                the single `betterAuth({...})` instance: database adapter, providers, session settings
src/lib/auth-client.ts         the client created with `createAuthClient()`
src/app/api/auth/[...all]/     the route that mounts the auth handler (path depends on the framework)
```

## Conventions

- Secrets (`BETTER_AUTH_SECRET`, OAuth client secrets) and `BETTER_AUTH_URL` come from environment variables.
- Auth tables are generated by the CLI into the project's own schema and migrations, then reviewed.
- Session checks happen on the server (`auth.api.getSession`), in middleware and in every protected route handler; the client only reflects state.
- Enable email verification and rate limiting before launch; password hashing stays at the library default or stronger.
- Cookies are `HttpOnly`, `Secure` in production, `SameSite=Lax`; trusted origins are listed explicitly.

## Commands

| Schema | `npx @better-auth/cli generate` |
| Secret | `openssl rand -base64 32` |

## Testing

- Tests sign in through the real handler against a test database; helpers create a user and return a session cookie.
- Cover: wrong password, expired session, access to another user's data, sign-out.

## Rules for agents

- Never trust a user id from the request body or client state; take it from the server session.
- Never log passwords, tokens or session cookies.
- Never disable email verification, CSRF or origin checks to make a test pass.
