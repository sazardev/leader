# STACK.md: T3 stack

## Summary

A typesafe full-stack application from create-t3-app: Next.js (App Router) for UI, tRPC for the API between client and
server without a schema file, Prisma (or Drizzle) for the database, Auth.js for sessions and Tailwind for styling.
Types flow from the database schema to the UI with no code generation step besides the ORM's. tRPC routers stay thin:
business rules live in services that know nothing about tRPC.

## Project layout

```
src/
  env.js                            Zod-validated env (@t3-oss/env-nextjs)
  app/                              routes only
    layout.tsx                      TRPCReactProvider
    page.tsx
    orders/page.tsx                 Server Component: prefetch with the server caller, HydrateClient
    api/trpc/[trpc]/route.ts        tRPC HTTP handler
    api/auth/[...nextauth]/route.ts
  trpc/
    react.tsx                       client provider and api hooks
    server.ts                       server caller for Server Components
  server/
    api/
      trpc.ts                       context, publicProcedure, protectedProcedure
      root.ts                       appRouter: merges feature routers
      routers/order.ts              thin: input schema → service → output
    auth/config.ts
    db.ts                           Prisma client singleton
    orders/
      order.ts                      domain types and rules
      order-repository.ts           interface
      order-repository.prisma.ts
      order-service.ts              use cases (place, cancel…)
      schemas.ts                    Zod inputs shared with forms
  features/orders/components/       OrderList.tsx, OrderForm.tsx ("use client" where needed)
prisma/
  schema.prisma
  migrations/
tests/e2e/
```

Dependency direction: `app/features (UI) → tRPC hooks → server/api/routers → server/<feature> services → domain`;
only `*-repository.prisma.ts` and `server/db.ts` import Prisma.

## Conventions

- One file = one responsibility: one router per feature, one service per feature (split by use case when it grows), one component per file.
- Routers only declare procedures: `.input(schema)` → call the service with `ctx` → return; no Prisma calls in routers.
- `protectedProcedure` for anything that needs a user; authorization (ownership, roles) is checked in the service.
- Services throw domain errors; one helper maps them to `TRPCError` codes.
- Server Components prefetch with the server caller and hydrate; Client Components use `api.x.y.useQuery`.
- Mutations invalidate with `utils.x.invalidate()` for the affected queries.
- Env only through `src/env.js`.
- New feature = domain + repository + service → router (added to `root.ts`) → components → route.

## Testing

- Services and domain: Vitest with in-memory repositories.
- Routers: `createCaller` with a fake context (session or none); assert auth errors and validation.
- Repositories: integration tests against a real Postgres (Docker), reset per test file.
- Playwright for sign-in and critical flows.

## Quality gates

- `tsc --noEmit` clean, no `any`, ESLint `--max-warnings 0`, Prettier clean.
- `prisma validate` and `prisma format` leave no changes; migrations committed.
- Vitest and Playwright green in CI; `next build` succeeds.

## Dependencies

- What create-t3-app installs, plus the table above; anything else needs a reason in the PR.
- Do NOT use: a REST layer next to tRPC for the same client, Redux, Axios, a second ORM, GraphQL, raw SQL strings with interpolation (`$queryRawUnsafe`).

## Rules for agents

- Never call Prisma from a router or a component; go through the feature's service and repository.
- Every procedure has a Zod `.input()`; never trust client input types.
- Use `protectedProcedure` for user data and check ownership in the service.
- Never edit an applied migration; create a new one with `prisma migrate dev`.
- Never read `process.env` directly; add the variable to `src/env.js`.
- After a mutation, invalidate the affected queries; do not refetch the world.
- Do not expose Prisma models directly from procedures: return explicit DTOs.
- Keep `root.ts` as the only place routers are merged.
