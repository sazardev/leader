# my-nvim-setup

Neovim + NvChad v2.5 config — not an application. No CI or build system; the only automatic checks are `scripts/gen-cheatsheet.sh --check` and `scripts/test-agent.sh` (agent parsers and target, no network).

## Repo structure

- `install.sh` / `install.ps1` — ONE-COMMAND installer (Linux/WSL/macOS · Windows; `curl … | bash` bootstraps by fetching the repo into `~/.local/share/my-nvim-setup`, non-interactive by default, `--ask` prompts, `--agent` defaults to `auto`, plugins via `Lazy! restore`, per-step timings): dependencies, Neovim ≥ 0.11, `nvim/` link, hooks, plugins, Mason and parsers; `--lang a,b` leaves only those languages (writes `languages.disabled` to `lua/local.lua`, without overwriting an existing one). Per-machine options: `--lang`, `--theme`, `--light/--no-light` (written to `lua/local.lua` by `scripts/install-local.lua`, ONE implementation shared by `install.sh` and `install.ps1`, never overwriting an existing `local.lua`) and `--agent auto|backend/model|none` (uses `scripts/agent-setup.sh`; skipped with `--no-plugins`). Uses `scripts/install-mason.lua`, `scripts/install-treesitter.lua` and `install-local.lua`; tests in `scripts/test-install.sh`; `scripts/test.sh` runs all the suites. `VERSION` is the config version (bumped with `chore(release)` + tag `vX.Y.Z`)
- `nvim/` — mirrors `%LOCALAPPDATA%\nvim` on Windows. Symlink it (or use the installer):

  ```powershell
  New-Item -ItemType Junction -Path "$env:LOCALAPPDATA\nvim" -Target "C:\path\to\my-nvim-setup\nvim"
  ```

- `.agents/skills/caveman*` — OpenCode skills (lockfile: `skills-lock.json`)
- `CHEATSHEET.md` — **GENERATED**, don't edit: all the keys (leader menus, LSP, completion, nvim-tree, globals) read from the real keymaps by `scripts/gen-cheatsheet.sh`; the `.githooks/pre-commit` hook regenerates it if the commit touches `nvim/`. `scripts/gen-cheatsheet.sh --check` fails if it is stale. It is the ONLY source of keys: don't copy key tables into the docs
- `docs/cheatsheets/` — only what is NOT derived from code (what each thing does, workflows, tools, pitfalls): `README.md` + one page per language (`go.md` is the most detailed). When changing a language's menus, snippets or tools, update its page; no key tables (those come from the code)
- `scripts/` — `gen-cheatsheet.sh` (+ `.lua`): cheatsheet generator (headless nvim with the real config, ignores `local.lua` via `NVIM_NO_LOCAL=1`)
- `scripts/test-agent.sh` (+ `test-agent.lua`, `test-agent-backends.lua`, `fake-llm.py`): inline agent tests (protocol, parsers, diff, target, local backends and setup against fake Ollama/OpenAI servers); no network or tokens
- `scripts/agent-setup.sh`: setup of local backends and models from the terminal (report, `--start`, `--pull`, `--auto`, `--use`, `--json`)
- `.gitignore` — excludes `.claude/` (machine-specific Claude config)

## How it works

- Plugins auto-install via `lazy.nvim` on first open
- Activate the auto-reload hook once per clone: `git config core.hooksPath .githooks` (the hook picks the right data dir for Windows or Linux)
- LSP servers and tools (gopls, vtsls, stylua, prettier, eslint_d, dart, etc.) auto-install via `mason-tool-installer`
- No manual setup beyond the symlink (or `./install.sh`, which also leaves plugins, tools and parsers already installed). A plugin with a heavy `build` that depends on a language must carry `enabled` according to `languages.disabled` (see `plugins/languages/go.lua`), otherwise `--lang` would install its tools anyway
- **Auto-reload**: `.githooks/post-merge` creates a marker on `git pull`; `core/autocmds/reload.lua` detects it on `UIEnter` and runs `luafile $MYVIMRC` to reload config automatically

## Architecture

One file = one responsibility. Minimal entry point in `nvim/init.lua`; everything else is modular:

```
nvim/
├── init.lua                  # bootstrap only (lazy + core)
└── lua/
    ├── core/                 # startup: settings, light, lazy, options, clipboard, theme
    │   ├── settings.lua      #   ALL configurable settings (+ local overrides)
    │   ├── keymaps/          #   cleanup (removes NvChad's) · general
    │   └── autocmds/         #   reload · treesitter · ui
    ├── languages/            # 1 file per language: DECLARES treesitter, lsp, mason, formatters, linters, menu
    │   ├── init.lua          #   registry: aggregates the declarations and serves them to each consumer
    │   └── actions/          #   menu actions (go, dart, typescript, python, rust, jvm...)
    ├── appearance/           # default theme vs terminal-inherited (Alacritty → base46)
    ├── themes/               # base46 user themes (terminal.lua is generated from the palette)
    ├── servers/              # per-LSP-server overrides (servers/<name>.lua) + loader
    ├── agent/                # inline agent (<leader>a): backends/ actions/ context/ output/ ui/ handoff/ (see below)
    ├── menus/                # contextual leader menus (buffer-local) + Git context
    ├── plugins/<group>/      # 1 lazy spec per plugin: core lsp tools syntax languages navigation editing git ui
    ├── ui/                   # start/ (start screen) + dashboard.lua (its buttons), arts/ (braille art catalog), highlights, lualine, flat/ (the flat design)
    ├── utils/                # pure helpers: terminal, project, actions, git, log, telescope
    └── chadrc.lua            # only composes: theme + dashboard + NvChad ui
```

**Adding a language**: create `lua/languages/<name>.lua` (contract in `languages/init.lua`) and add it to `NAMES`. There is no need to touch mason, treesitter, conform, nvim-lint or LSP: they come from the registry. Overrides for a server: `lua/servers/<server>.lua`.

**Adding a plugin**: a file in `lua/plugins/<group>/`. New groups: add them to `GROUPS` in `core/lazy.lua`.

**Adding a dashboard art**: create `lua/ui/arts/<name>.lua` (returns the list of lines; **braille-dot art only**, U+2800–U+28FF, no ASCII/blocks). It is discovered automatically: `ui/arts/init.lua` scans the folder, with no list to maintain. It is chosen from the dashboard's "Change Art" button (`ca`); the choice is saved in `stdpath("state")/dashboard.json`. Initial value: `settings.dashboard.art`.

**File operations** (`lua/files/`, `<leader>F`; `a`/`r`/`d` inside nvim-tree use the same modals instead of nvim-tree's prompts, `<leader>nd`/`nx` are gone): acts on the row under the cursor in the tree, else on the current buffer's file (`target.lua`). New: one input, `;` separates several, a trailing `/` makes a folder, the first file opens (from the tree, the tree closes first like `<CR>`). Rename: pre-filled name, a `/` in it moves the file. Move: a picker of the project's folders (`ops.folders`: depth 5, skips `.git`/`node_modules`/`vendor`/`target`/`dist`/`build`/`.venv`, capped) plus "new folder…". Duplicate: `name_copy.ext`, `_copy2`… Delete: confirm modal (folder: contents count; unsaved open files warned) then `ops.trash` moves it to `stdpath("state")/trash/<stamp>-<name>` with an `index.json` (30 days) and `<leader>Fu` restores the last one, refusing to overwrite. `ops` never overwrites and falls back to copy+delete across file systems (EXDEV). After a move `buffers.renamed` renames the SAME buffers: `nvim_buf_set_name` leaves a ghost buffer with the old name (deleted by its previous name, not the folder's), and the next `:w` says "File exists" unless the buffer is reloaded from the new place (`edit!`), so unsaved lines are saved before and put back after; LSP servers get `workspace/willRenameFiles` (edits applied before) and `didRenameFiles`. Tests: `scripts/test-files.sh`.

**Settings panel** (`lua/prefs/', `<leader>S`): `<leader>Sp` is one flat list (a telescope dropdown, the same widget as the agent model selector) of what is worth changing without editing a file. A group is a file in `prefs/items/` returning items (`group`, `label`, `kind` toggle/choice/action, `id` = path in `core.settings`, `apply` for the live effect, `restart`; contract at the top of `prefs/init.lua`; new group = file + `NAMES`). Enter flips a toggle, steps through up to 3 values or opens a picker for more, and runs an action; the list reopens on the row you changed. A choice is written to `core.settings` in place (so every module that reads settings where it is used sees it at once) and saved by `prefs/store.lua` in `stdpath("state")/prefs.json` as a flat `path → value` map that `core/settings.lua` merges AFTER `local.lua` (and ignores under `NVIM_NO_LOCAL`, which keeps the cheatsheet machine-independent). A choice whose `value` is nil (light mode `auto`) removes the saved key. Items with their own persistence (diagnostic blocks, `utils/diagblocks.lua` `get`/`set`) have no `id` and read/write through their owner. Whatever is read once at startup (flat design, session autosave, light mode) is marked `restart` and says so; `conform` reads `format_on_save` through a function so `<leader>Sf` is live. `prefs/info.lua` (pure `lines(facts)`) and `prefs/update.lua` (`git pull --ff-only` on the clone, then `Lazy restore`; never merges). Tests: `scripts/test-prefs.sh`.

**Terminal-inherited theme** (`<leader>S`): reads `alacritty.toml` (Linux, Windows or WSL under `/mnt/*/Users/*/AppData`), resolves its `import`s and generates a base46 theme (`lua/themes/terminal.lua`) with the terminal's exact background, interpolated grays and accents with minimum contrast (`theme.terminal.min_contrast`; never dimmed toward the background, comments = the terminal's bright black). The flat design is FAITHFUL to it (`palette.from(..., { faithful = true })`): the editor stays on the terminal's background (`deep = bg`, so the rebase is a no-op and Neovim and the terminal are one surface) and `Visual` is the terminal's own selection color; only floats/panels (`soft`) step away from it. It is remembered across sessions (state in `stdpath("state")/appearance.json` + a marker next to the base46 cache) and followed LIVE: while the active theme is the terminal one, a poll (`theme.terminal.watch_ms`, 1000 ms; 0 = off) `stat`s the config files and recompiles when it detects a change (inotify doesn't work: on WSL the config lives on `/mnt/c`). With the default theme nothing runs. It also re-syncs when nvim opens and when focus returns. The compiled marker is SHARED by every open Neovim (it sits next to the shared base46 cache), so live updates (`appearance.refresh`, poll and `FocusGained`) compare against the signature THIS instance applied, never the marker: otherwise the first instance to recompile leaves all the others painted with the old palette. `sync` (marker) is only for startup. **Startup cost**: the marker also stores the parsed palette, the config path and its theme file; while the recorded files are untouched (`alacritty.unchanged`: only `stat`, memoized for 500 ms) `initial`, `sync`, `refresh` and `alacritty.load` use it instead of searching `/mnt/*/Users/*` and parsing TOML (on WSL that was ~60 ms per start and ~40 ms per focus return; now the terminal theme starts as fast as the default one). Custom path: `theme.terminal.config`.

**Sessions and Herdr**: `persistence.nvim` saves on exit and `core/autocmds/session.lua` also saves in the background every `session.autosave_ms` (only if something changed and without closing your auxiliary windows), so a power cut doesn't lose the state. Inside Herdr (`HERDR_ENV=1`) `utils/herdr.lua` registers nvim as an "agent" with the resume `nvim +HerdrResume` (a user command that restores the folder's session); on exit it releases it, so a normal `:q` doesn't reopen the pane. It doesn't override a real agent already occupying the pane. It is **off by default** (`session.herdr = false`): Herdr 0.9.x ignores the resume (needs >= 0.10.0) and nvim showed up in the Agents panel with no benefit. Enable: `session = { herdr = true }` in `local.lua`; `autosave_ms = 0` disables autosave.

**Inline agent** (`lua/agent/`, `<leader>a` menu, doc in `docs/cheatsheets/agent.md`): ONE-shot actions (implement, review, explain, ask, fix, document, refactor, hand off to Herdr) on the function under the cursor or the selection, with no chat or sidebar. One folder, one contract per piece: `backends/<cli>.lua` (`build`/`parser`; claude, opencode, **ollama**, **openai** (LM Studio/llama.cpp/vLLM) and `command` for CLIs declared in `agent.custom`), `actions/<action>.lua` (target, context, prompt, output), `context/` (treesitter target + budgeted providers: rules, **types** the target uses (treesitter + LSP, any language), LSP signatures, diagnostics with their line, outline), `output/<kind>.lua` (presenters: `replace` = inline diff with accept/reject, `findings` = diagnostics, `text` = window with streaming), `ui/` (spinner, preview, window, picker). Adding a backend/action/presenter/provider = one file + its `NAMES` list; the menu comes from the action registry. `protocol.lua` keeps the output format demanded of the model TOGETHER with its parser. Settings in `settings.agent`; the backend+model chosen with `<leader>am` are saved in `stdpath("state")/agent.json`. **Local models and setup** (`backends/{http,ollama,openai,command}.lua`, `setup/`): `setup/detect.lua` measures CLIs, servers (incl. the Windows host from WSL) and GPU/RAM in parallel without touching anything; `recommend.lua` (pure) proposes models by VRAM; `actions.lua` is the only thing that modifies (start `ollama serve`, `/api/pull`, remember `endpoints`, set backend/model); open it with `<leader>am` → Setup or `scripts/agent-setup.sh`. Ollama sizes `num_ctx` per request (otherwise it truncates silently) and `light_backend` leaves docs/explain on a local model without moving the main one. Everything loads lazily (the `agent` facade only on first use; lualine looks at `package.loaded`). Measured pitfalls: `claude -p` by default drags ~46k input tokens, with `--setting-sources "" --tools "" --system-prompt` ~600 (**don't use `--bare`**: it disables the OAuth login); the CLIs run in `stdpath("cache")/agent` (without the repo's AGENTS.md); opencode falls back to the default agent (with tools) if it can't find the requested one, **opencode latency** (measured, `opencode-go/deepseek-v4.1-flash`, one-line task): cold `opencode run` ~7-9 s and ~20k input tokens because the global MCP servers' schemas ride along (`agent.opencode.mcp=false` disables them by name, ~5 s and ~830 tokens); a private `opencode serve` + HTTP `POST /session/:id/message` (`backends/opencode_server.lua`, session created ahead, basic-auth password) is ~2 s; `run --attach` (v1.19) emits no text, so it is not used; the **2.x CLI** (measured, 2.0.31) is detected by `v2()` in the same file and changes the shape (`agents`/`system`/`permissions`, variant in `-m model#variant`, `run --standalone` because the background service never sees the inline config, no `--pure`; warm server off until its v2 HTTP API is driven, ~3 s per action, and its JSON stream carries no usage events); `vim.system{cwd=}` does not update `$PWD` and opencode resolves its project from it, so `runner.lua` sets `PWD` (otherwise the repo's AGENTS.md/CLAUDE.md, ~10k tokens, leaked into every prompt); `opencode run` hangs waiting on an inherited stdin when called by hand without `</dev/null`; and its route could not be tested with network in the development environment (parser and command were, with synthetic events and `scripts/test-agent.sh`). `.agent.md` at the project root adds conventions to every prompt. **DDD** (`lua/agent/ddd/`, `<leader>aD` menu, a separate feature): local static analysis of layers, imports, naming and aggregates (port/implementation/wiring/use cases) that costs 0 tokens (`diagnose`: diagnostics, quickfix and panel), and LLM actions (`implement`, `review`, `missing`, `ask`) with their own registry (`ddd/actions`) that reuse the same pipeline and receive the `<ddd>` section (provider `context/providers/ddd.lua`). Only what is inside layer directories is read; settings in `agent.ddd`. **Hexagonal architecture levels**: one folder and one menu per level — `agent/ddd/` (`<leader>aD`), `agent/repository/` (`<leader>aP`: port, implement, review, check), `agent/service/` (`<leader>aU`, use cases: implement, review, deps) —, each with its own action registry (same contract and pipeline as `agent/actions`) and a local 0-token analysis; what is shared (rg, type reading) lives in `agent/discovery.lua`; `<leader>a` is left for generic things. **Project documents** (`agent/kit/`, `<leader>aS`, not a level: it writes files, not code): AGENTS.md (model reads `snapshot.collect`: tree, languages, manifests, Makefile targets, scripts, README; `A` = 0-token `template.lua`), STACK.md (stack presets per category + principle presets appended by `compose.set_principles`), DESIGN.md (design-system presets, or described with a named preset as `<base>`), SPEC.md (free text in `draft.lua` → requirements/acceptance criteria/open questions); sections fixed in `compose.DOCS` and checked on every preset by `scripts/test-kit.sh`; replace = confirm + `files.ops.trash`; new documents are linked from AGENTS.md "Read first"; `c` makes CLAUDE.md import `@AGENTS.md`. **Build with agent** (`agent/kit/build/`, `<leader>aSb`): phases ready → plan → review → write → check → fix → **use** → look → done. Quality harness, each piece one file: `clean.lua` (pure: a model's answer as a file — fences with prose, echoed `<file>` tags, leaked tool-call markup such as DeepSeek's `｜DSML｜` and leading chatter go; `problem()` says what is still not a file and the request is asked again ONCE, `prompt.again`; a broken fix keeps the old file), `wiring.lua` (pure, 0 tokens: names the plan's `exports` promise that no other non-test file mentions; methods must appear as `.Name` (a style called `Expression` must not hide `Calculator.Expression()`), lists like `Title, Muted styles` split, framework hooks (`Init/Update/View/String/Error`, bubbles' `ShortHelp/FullHelp`…) excluded; behaviours fail the check, values only feed the use verdict), the plan's `wiring` rows (FR → user action → code → what they see) go into every file's cached system prompt, and `use/` (the app driven as its user: `launch.lua` recognizes the kind from the manifest and code, never from the model; `scenario.lua` writes scenarios ONCE per build from SPEC/DESIGN — expectations never from the code — and every round replays them; `drivers/` tui (private tmux server `-L`, `-f` own conf, the app under `sh -c '…; printf "[exited with %s]"; sleep'` because a dead pane loses its output; keys ONE at a time: a burst reaches Bubble Tea as one KeyMsg that no binding matches), cli, web (+ Electron; `web_runner.cjs` with the project's or the global Playwright, the server started detached and killed as a group), android (adb + uiautomator, needs a device you started); `judge.lua` free checks per frame + one verdict request whose free failures it can never overrule; `async.lua` runs a driver as a coroutine so the editor never blocks). Goldens are trashed before any use/look fix and looked at again (`look_rounds`, `use_rounds`). New driver = one file with `available/prepare/play/finish` + its line in `use.DRIVERS`. Fixes are **edit blocks** (`edits.lua`, pure: SEARCH/REPLACE applied line-wise, trailing spaces ignored, ambiguous or missing SEARCH refused; `shrunk` catches a fragment taken for the file; the one retry after failed blocks asks for the whole file). Every model JSON goes through `clean.json` (first `{` to last `}`, then `%b{}`: Lua's `%b{}` alone cuts at a `}` inside a string; `vim.json.decode` rejects an explicit nil `opts`); invalid scenarios or verdict JSON is asked again once. Free checks: `verify.unhandled_actions` (`data-action|key|op|command…` names, words of 3+ letters, that no script mentions), `verify.drop_versions` (invented Go pseudo-versions → `go mod edit -droprequire`), `plan.generated` (goldens, lockfiles, build output are never planned); `not_see` shorter than 3 characters is ignored (a keypad shows every digit). The verdict reads the wiring code (`scenario.controls`) and only the rows that changed per step (`judge.delta`); `fix_round` resets per repair cycle and `live.user` carries the use findings into the next diagnoses. Measured on calc-lab (opencode deepseek-v4.1-flash): see `docs/cheatsheets/agent.md`. Tests: `scripts/test-kit-use.lua` (run by `scripts/test-kit.sh`; tmux and Playwright parts run for real when installed). **Tests** (`agent/tests/`, `<leader>aT`: write/mock/fix + local gaps) and **lenses** (`agent/lenses/`, `<leader>aL`: security/performance/concurrency/errors/api, they come out as diagnostics with their origin) are two more levels with their own registry and menu. The pipeline recognizes action hooks: `retarget` (the result goes to ANOTHER file; the target becomes the end of the test file and the original is the `subject` the context comes from, with `job.view` so the spinner shows on the tested code), `merge` (the model returns only what is new, `protocol.APPEND_RULES`), `reveal` (opens the destination to the side) and `prepare` (prior work WITHOUT a model, e.g. running the test: if it passes, 0 tokens); lenses use `gate` (words: with none, they don't call the model). The findings of a lens only replace those with the same `source`. Adding a level = folder + registry + `menus/agent_<level>.lua` + line in `menus/init.lua`. **Adapters** (`agent/repository/contracts/`, providers `contracts` and `schema`, Repository-level actions in `<leader>aP` (port, implement, review, check)): if the target is an adapter (e.g. `PostgresOrderRepository`) the following are injected, with their path: the port it implements (by name or `implements`/`impl X for`/`var _ X`, searched with rg), the missing methods, the entity the port names, a sibling implementation as a style example and the real table (SQL/Prisma migrations) with dialect/driver/parameters; silent if the code is not an adapter; scope `type` = the type under the cursor or its receiver's. **Persistent findings** (`agent/persist.lua` + `core/autocmds/agent.lua`): those from `review`/`ddd review`/`ddd diagnose` are saved in `stdpath("state")/agent-findings.json` with their line's text and restored (re-anchored) when the file is opened; `fix` and `ddd fix` read them via the `findings` provider and, on accept, the resolved ones are removed. `<leader>ax` stop does NOT delete them; they are cleared one at a time with `<leader>ac` clear (cursor line or selection), with `<leader>aC` (file) or with `:AgentClear [file|all]`. Two models per backend (tiers `main`/`light`; docs and explain go to the light one, `<leader>am` → Light model); `i`/`d`/`f` open the inline instruction field (empty Enter = no instruction), `a`/`R` require it. Short menu: i d r e a f R g(handoff, Herdr only) h(history) m x l (plus c/C clear). **Two-level fix**: `f` = inline (target = the lines of the diagnostic under the cursor, scope `diagnostic` in `context/target.lua`; it carries `<around>` and, via the LSP's `typeDefinition` on the diagnostic's identifiers, the types they point to) and `F` = block (the whole function, same types). `runs/` saves every run in `stdpath("state")/agent-history.jsonl` (prompt, response, tokens, cost, what you did with it) and `<leader>ah` shows it with a spend report; `claude -p` runs with `DISABLE_PROMPT_CACHING=1` (the cache only charged writes: -40 % per call). The colors in `agent/ui/highlights.lua` are derived from the theme palette (no linking to Diff*/Comment) and recomputed on `User NvThemeReload`.
**Advanced menu**: the batch features are not in the everyday `<leader>a`; actions flagged `advanced = true` (fix all `a`, fix from output `o`/`O`, plan `p`) and the proposal queue (`]` `[` `y` `l`, labels from `batch/queue.lua`) are bound under `<leader>aA` by `menus/agent_advanced.lua`. A new batch-style action sets the flag and picks a key unused in THAT menu.

**Agentic layer** (`lua/agent/`: `events`, `guards/`, `budget`, `verify/`, `refine`, `batch/`, `fixall/`, `errors/`, `review/`, `plan/`; doc in `docs/cheatsheets/agent.md`): features that hang off the inline agent's pipeline WITHOUT editing the flow they hang from (the open/closed rule of this folder). `events.lua` is a tiny pub/sub (`proposal.accepting`/`accepted`/`dropped`, `job.settled`; handlers run in `pcall`), `features.lua` is the composition root that wires listeners (`verify`) and is called when the pipeline loads. `pipeline.run(action)` resolves the target from the cursor and asks the instruction, then calls `pipeline.launch(spec)` (action, target, subject, selection, input, `extra` sections, `meta`, `preapproved`): every other feature launches through `launch` with a target it already knows. `action.standalone = true` skips target resolution and calls `action.handler({ selection, action })` (fix all, fix from output, plan: all in the Advanced menu). `guards/init.lua` runs after the prompt is built and BEFORE the request: `check(req)` per guard (`budget` is the first; add one = file + `NAMES`) returns nil, `block` (notification, job `denied`) or `confirm` (one modal with every reason, `utils.modal.confirm` with `opts.on_cancel` so a "no" releases the job: `runner.deny` records nothing and emits `job.settled` `denied`). `budget.lua` is PURE (tokens ≈ chars / 3.5, price per token learned from the history of that model, caps `day_usd`/`session_usd` block, `confirm_tokens`/`confirm_usd`/`warn_ratio` ask); `runs.call` records one-shot calls (commit draft, staged review, plan: `output = "oneshot"`) so the spend is complete, and `runs/advice.lua` (pure) feeds the report's Budget/Suggestions. **Answer cache** (`cache/`: pure `core.lua` = key/eligible/prune, `init.lua` = file in `stdpath("state")/agent-cache.json`): `pipeline.launch` asks `cache.lookup(job)` right after the prompt is built and BEFORE the guards; the key is the sha256 of backend+model+effort+system+prompt, so any change to code, context, diagnostics or instruction misses; a hit goes through `runner.settle` (the same path a model answer takes, 0 tokens, `stats.line` says `cached`) but is NOT recorded in `runs/`: it is not a model call, so history and spend report stay about real runs, and the cache keeps its own counters (`cache.stats()`: hits, tokens and cost saved, shown by `<leader>aAk`), a success stores in `runner`. Only `text`/`findings` outputs by default (`settings.agent.cache.outputs`, `action.cache = true|false`): a `replace` proposal is never reused. `meta.fresh` skips the lookup. Tests MUST NOT touch the real cache (`K.fake()` points it at a temp file), `<leader>aAk` shows its stats and clears it. **Keys a hint advertises must work where the cursor is**: the answer window (`ui/float.lua`) never takes focus, so `float.enable_followup()` binds the follow-up key on the code buffer while the answer is shown (released on close, `WinClosed` or cursor move; `replace.rebind` gives it back to a waiting proposal, and `replace.unbind` only deletes mappings whose desc says `proposal`). `float.dismiss()` is what the global `<Esc>` (`core/keymaps/general.lua`, after the diagnostic popup) calls to close the answer from the code (and to stop a call still streaming). Test: `scripts/test-agent-keys.lua`. **Next edit** (`actions/next.lua`, `edits.lua`, provider `edits`, scope `window` in `context/target.lua`, wired by `core/autocmds/agent.lua`: `BufEnter` baseline, `InsertLeave`/`TextChanged` record): `edits.hunks`/`render` are pure; **Project tasks** (`lua/tasks/`, `<leader>R`, menu `menus/tasks.lua`, doc in `docs/cheatsheets/tasks.md`): the targets of the project's Makefile in ONE picker, 0 tokens, nothing resident. It works with a Makefile and ONLY with a Makefile: every action (`r` `l` `d` `a` `p` `o` `q` `s`) calls `tasks.need(dir)` first, which says "no Makefile above … (<leader>Rc creates one from a preset)" and does nothing; there are no other runners on purpose (just, task, mise and package.json scripts were removed). `make.lua` finds the Makefile (`GNUmakefile` > `makefile` > `Makefile`, nearest at or above the current file's folder, never above the git root: `util.stop`, so the machine's `~/Makefile` is not the project's) and lists its targets. A task is a `.PHONY` target or a described one (with neither, every plain target). Pure parsers: `parse_db`, `parse_file`, `build`. `init.lua` caches per Makefile (mtime+size of it and its `*.mk`, `<C-r>` in the picker forces), sorts (default goal first, then the file's order) and owns the flows (`pick`, `last`, `default` = a bare `make`, `ask`, `dry` = `make -n`, `quickfix`, `create`). The first line is a `# description` comment (it stays in the created file), every target carries `## text` (so the picker lists it) and every preset has a `help` target; recipe lines MUST use tabs. Creating asks language (the one the project looks like first: `presets.guess` from marker files, else the filetype) then preset with the file as preview, writes `<git root>/Makefile` and opens it; it never overwrites and does nothing when a Makefile exists above. `scripts/test-tasks.sh` runs a REAL make over every preset (`make -qp` must read it, `.PHONY` must include `help`, every listed target needs a description). `settings.tasks.timeout_ms`. Tests: `scripts/test-tasks.sh`.

## Gotchas

- **Clipboard (WSL/SSH without DISPLAY)**: `core/clipboard.lua` uses OSC 52 to copy (Alacritty + herdr forward it); pasting from the system is Ctrl+Shift+V in the terminal
- **Undo, redo, clipboard, yank history** (`lua/history/`, global `<leader>u` menu, knobs in `settings.history` and `settings.clipboard.keep`): `undo.lua` splits an insert into undo steps like VS Code (after whitespace, a new line, or a `pause_ms` pause) by feeding Vim's own `<C-g>u` from `TextChangedI` / a timer, ONLY when `getchar(1) == 0` and no register is executing: with keys still queued (a macro, `.`, fast typing) the `<C-g>u` would land in normal mode as `<C-g>` + `u` and undo the replay. `vim.o.undolevels = vim.o.undolevels` does not break undo inside insert mode, so feeding is the only way; `.` still repeats the whole insert. `u` / `<C-r>` / `U` / `<C-y>` / `<C-z>` run `normal! u`/`<C-r>` silently and flash the `'[`..`']` lines (`ui.flat.fresh`); `<leader>uu` is Neovim's built-in `:Undotree` (`packadd nvim.undotree`, moving in it moves the buffer), `<leader>u[`/`]` are `:earlier 1f`/`:later 1f` (the file at the previous/next save). `yanks.lua` keeps every TextYankPost newest first without duplicates, writes `stdpath("state")/yanks.json` on exit (merged with what another nvim saved; `clear` writes at once or the merge would bring entries back); `p`/`P` are wrapped to remember the paste so `[y`/`]y` can undo it and put an older/newer entry through a borrowed `z` register (restored). With `clipboard.keep`, `x X c C` are expr maps returning `"_x`… only for the default register (an explicit `"ax` still copies) and visual `p` returns `P`; they are mapped AFTER `menus.setup()` because loading which-key makes lazy delete the `c` stub of NvChad's spec, which would take our `c` with it. `ui/flat/keys.lua` ignores the fed `<C-g>u`. Tests: `scripts/test-history.sh` (types into a child nvim with `nvim_input`, one key at a time).
- **ysc (YarnSpinner linter)** is optional: it is enabled only if `ysc` is on the PATH (`dotnet tool install -g yarn-spinner`, requires `dotnet`)
- **`:checkhealth mason`** warns about missing ruby/gem/php/java/julia/composer/luarocks: it is informational only, no tool in the config needs them
- **Contextual leader menus** (`lua/menus/` + each language's `menu` field): each language has its own letter and only exists in buffers of that filetype (g Go, d Dart, r Rust, p Python, t TS/JS, m Markdown, s CSS, j Java, k Kotlin); `<leader>G` Git only inside a repo. To add a language: a new entry in the `langs` table. Don't define a mapping that is both an action and a prefix of others (e.g. `<leader>h` + `<leader>h1`): which-key resolves it after `timeoutlen` and closes the popup
- **Long comments** (global `<leader>C` menu, `utils/comments.lua`): detects with treesitter (nodes `comment`, `line_comment`, `block_comment`... whichever exist in the grammar) blocks and runs of consecutive lines that are alone on their line, of `comments.min_lines`+ lines, and `plugins/editing/ufo.lua` adds them to nvim-ufo's folds with `kind = "comment"` (it doesn't duplicate those the provider already folds). `Cc` folds and saves the "folded" preference (global, `stdpath("state")/comments.json`; `comments.auto_collapse` is only the initial value), `Ce` unfolds and turns it off, `Ct` toggles the one under the cursor without touching it. With the preference on, ufo closes the folds of `kind = "longcomment"` (its own kind: treesitter's uses the node name and would also close the short ones) when each buffer is first shown: `comments.sync_ufo` adds/removes that kind in the LIVE list `require("ufo.config").close_fold_kinds_for_ft.default`; a `BufWinEnter` aligns the buffers that already existed and folds NOW (`fold_now`: synchronous `:fold` + close, before the first redraw) the newly opened buffers, because ufo's provider is asynchronous and let the opened file show for a few tens of ms; ufo then rebuilds the folds and closes them by kind without it being noticeable. - **Code folds** (global `<leader>z` menu, `utils/folds.lua`, `menus/folds.lua`): closes folds by what the code IS, on top of nvim-ufo's folds. `f`/`t`/`o` fold the function / type / object literal under the cursor (pressing again walks outwards: closure → its function), `b` the innermost fold (`zc`, again = the one around it), `m` the methods of the type you are in (type stays open), `F`/`T`/`O` every function / type / object in the file, `a` outline only, `e` expand all, `s` focus (everything closed except what contains the cursor), `u` unfold here and inside (`zO`), `z` toggle (`za`), `1`-`3` fold everything nested deeper than that level (`ufo.closeFoldsWith`). Functions and types come from the `textobjects` queries (`@function.outer`, `@class.outer`, via `agent/context/scopes.lua`, same definition as `af`/`ac`); objects have no query, so `utils/folds.lua` matches EXACT node types (`OBJECT`: a substring match would catch argument lists and `map_type`s): add a language's literal there. `close()` closes the range's own fold; if the line has none (one-liner, ufo not done yet) `:foldclose` would hit the PARENT fold, so that is undone and a manual fold is made instead (ufo may redraw it on the next change). Ranges are closed inner-first (later start first). Single-line nodes are never folded. The long-comment folds have their own menu (`<leader>C`); `e` here also opens them.
- **Conventional commits** (`lua/commit/`, `<leader>G` menu: `Gc` panel, `Gm` panel + AI draft, `GM` automatic commit without a panel, `Ga` amend): ONE panel (`commit/panel.lua`, three stacked floats: files, an `acwrite` message with filetype `gitcommit`, and an agent status line below, because `virt_lines_above` on row 0 doesn't get drawn) with the three entry points of `commit/init.lua`. One folder, one responsibility: `conventional.lua` (PURE: `split`, `parse_header`, `check` for the live indicator, `rewrite` of type/scope, `suggest_type/scopes`, `clean_message`), `git.lua` (status with +/− per file via `--numstat`, stage/unstage, async commit, branch/upstream), `ai.lua` (prompt + `describe`, which announces in the panel what will be sent BEFORE spending anything), `auto.lua` (`GM`: no panel and in the background), `highlights.lua` (derives from the `Agent*` ones, which come from the theme), `panel.lua` (UI). The AI goes through `require("agent").complete` (`agent/oneshot.lua`: same backend/model as the actions, light tier reassignable with `agent.tiers.commit`, returns `usage` as the callback's 3rd argument); the draft is never requested on its own (except `Gm`) and replaces the message in an undoable way. **The AI message ALWAYS comes out in English and on a single line** (Conventional header; there is no language setting). It is fast on purpose: COMPACT diff (`git.diff_for_ai`: no git headers, `-U1`, no lockfiles/maps/snapshots, `diff_max_chars` cap split among files; `--src-prefix=a/ --dst-prefix=b/` forced, because a global `diff.mnemonicPrefix` writes `c/ i/ w/` and the parser saw NO files: the draft lost the diff, same in `agent/review/init.lua`), the branch and the types; subjects of previous commits are NOT sent (the model copied their language; the scope vocabulary is computed locally). Measured with haiku: ~2 s and ~$0.0004. `GM`: if there are staged files it commits only those; otherwise it stages everything modified except `git.commit.sensitive` (`.env`, keys...), asks for the message, validates the header and commits; if anything fails (no backend, AI, invalid header, hook) it undoes what it staged and warns. The types and limits live in `settings.git.commit` and the `.githooks/commit-msg` hook repeats the type list (shell): keep them identical. Pitfall: the close by `WinClosed` arrives queued; compare with the current panel before closing or it will close the next one you open. Tests: `scripts/test-commit.lua` (temp repo, fake backend, whole panel).
