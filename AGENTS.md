# my-nvim-setup

Neovim + NvChad v2.5 config — not an application. No CI or build system; the only automatic checks are `scripts/gen-cheatsheet.sh --check` and `scripts/test-agent.sh` (agent parsers and target, no network).

## Repo structure

- `install.sh` / `install.ps1` — ONE-COMMAND installer (Linux/WSL/macOS · Windows; `curl … | bash` bootstraps by fetching the repo into `~/.local/share/my-nvim-setup`, non-interactive by default, `--ask` prompts, `--agent` defaults to `auto`, plugins via `Lazy! restore`, per-step timings): dependencies, Neovim ≥ 0.11, `nvim/` link, hooks, plugins, Mason and parsers; `--lang a,b` leaves only those languages (writes `languages.disabled` to `lua/local.lua`, without overwriting an existing one). Per-machine options: `--lang`, `--theme`, `--light/--no-light` (written to `lua/local.lua` by `scripts/install-local.lua`, ONE implementation shared by `install.sh` and `install.ps1`, never overwriting an existing `local.lua`) and `--agent auto|backend/model|none` (uses `scripts/agent-setup.sh`; skipped with `--no-plugins`). Uses `scripts/install-mason.lua`, `scripts/install-treesitter.lua` and `install-local.lua`; tests in `scripts/test-install.sh`; `scripts/test.sh` runs all the suites. `VERSION` is the config version (bumped with `chore(release)` + tag `vX.Y.Z`)
- `nvim/` — mirrors `%LOCALAPPDATA%\nvim` on Windows. Symlink it (or use the installer):

  ```powershell
  New-Item -ItemType Junction -Path "$env:LOCALAPPDATA\nvim" -Target "C:\path\to\my-nvim-setup\nvim"
  ```

- `.agents/skills/caveman*` — OpenCode skills (lockfile: `skills-lock.json`)
- `CHEATSHEET.md` — **GENERATED**, don't edit: all the keys (leader menus, LSP, completion, nvim-tree, globals) read from the real keymaps by `scripts/gen-cheatsheet.sh`; the `.githooks/pre-commit` hook regenerates it if the commit touches `nvim/`. `scripts/gen-cheatsheet.sh --check` fails if it is stale. It is the ONLY source of keys: don't copy key tables into the docs
- `docs/cheatsheets/` — only what is NOT derived from code (what each thing does, workflows, tools, pitfalls): `README.md` + one page per language (`go.md` is the most detailed). When changing a language's menus, snippets or tools, update its page; no key tables (those come from the code)
- `scripts/` — `gen-cheatsheet.sh` (+ `.lua`): cheatsheet generator (headless nvim with the real config, ignores `local.lua` via `NVIM_NO_LOCAL=1`)
- `scripts/test-agent.sh` (+ `test-agent.lua`, `test-agent-backends.lua`, `fake-llm.py`): inline agent tests (protocol, parsers, diff, target, local backends and setup against fake Ollama/OpenAI servers); no network or tokens
- `scripts/agent-setup.sh`: setup of local backends and models from the terminal (report, `--start`, `--pull`, `--auto`, `--use`, `--json`)
- `.gitignore` — excludes `.claude/` (machine-specific Claude config)

## How it works

- Plugins auto-install via `lazy.nvim` on first open
- Activate the auto-reload hook once per clone: `git config core.hooksPath .githooks` (the hook picks the right data dir for Windows or Linux)
- LSP servers and tools (gopls, vtsls, stylua, prettier, eslint_d, dart, etc.) auto-install via `mason-tool-installer`
- No manual setup beyond the symlink (or `./install.sh`, which also leaves plugins, tools and parsers already installed). A plugin with a heavy `build` that depends on a language must carry `enabled` according to `languages.disabled` (see `plugins/languages/go.lua`), otherwise `--lang` would install its tools anyway
- **Auto-reload**: `.githooks/post-merge` creates a marker on `git pull`; `core/autocmds/reload.lua` detects it on `UIEnter` and runs `luafile $MYVIMRC` to reload config automatically

## Architecture

One file = one responsibility. Minimal entry point in `nvim/init.lua`; everything else is modular:

```
nvim/
├── init.lua                  # bootstrap only (lazy + core)
└── lua/
    ├── core/                 # startup: settings, light, lazy, options, clipboard, theme
    │   ├── settings.lua      #   ALL configurable settings (+ local overrides)
    │   ├── keymaps/          #   cleanup (removes NvChad's) · general
    │   └── autocmds/         #   reload · treesitter · ui
    ├── languages/            # 1 file per language: DECLARES treesitter, lsp, mason, formatters, linters, menu
    │   ├── init.lua          #   registry: aggregates the declarations and serves them to each consumer
    │   └── actions/          #   menu actions (go, dart, typescript, python, rust, jvm...)
    ├── appearance/           # default theme vs terminal-inherited (Alacritty → base46)
    ├── themes/               # base46 user themes (terminal.lua is generated from the palette)
    ├── servers/              # per-LSP-server overrides (servers/<name>.lua) + loader
    ├── agent/                # inline agent (<leader>a): backends/ actions/ context/ output/ ui/ handoff/ (see below)
    ├── menus/                # contextual leader menus (buffer-local) + Git context
    ├── plugins/<group>/      # 1 lazy spec per plugin: core lsp tools syntax languages navigation editing git ui
    ├── ui/                   # start/ (start screen) + dashboard.lua (its buttons), arts/ (braille art catalog), highlights, lualine, flat/ (the flat design)
    ├── utils/                # pure helpers: terminal, project, actions, git, log, telescope
    └── chadrc.lua            # only composes: theme + dashboard + NvChad ui
```

**Adding a language**: create `lua/languages/<name>.lua` (contract in `languages/init.lua`) and add it to `NAMES`. There is no need to touch mason, treesitter, conform, nvim-lint or LSP: they come from the registry. Overrides for a server: `lua/servers/<server>.lua`.

**Adding a plugin**: a file in `lua/plugins/<group>/`. New groups: add them to `GROUPS` in `core/lazy.lua`.

**Adding a dashboard art**: create `lua/ui/arts/<name>.lua` (returns the list of lines; **braille-dot art only**, U+2800–U+28FF, no ASCII/blocks). It is discovered automatically: `ui/arts/init.lua` scans the folder, with no list to maintain. It is chosen from the dashboard's "Change Art" button (`ca`); the choice is saved in `stdpath("state")/dashboard.json`. Initial value: `settings.dashboard.art`.

**Terminal-inherited theme** (`<leader>S`): reads `alacritty.toml` (Linux, Windows or WSL under `/mnt/*/Users/*/AppData`), resolves its `import`s and generates a base46 theme (`lua/themes/terminal.lua`) with the terminal's exact background, interpolated grays and accents with minimum contrast (`theme.terminal.min_contrast`). It is remembered across sessions (state in `stdpath("state")/appearance.json` + a marker next to the base46 cache) and followed LIVE: while the active theme is the terminal one, a poll (`theme.terminal.watch_ms`, 1000 ms; 0 = off) `stat`s the config files and recompiles when it detects a change (inotify doesn't work: on WSL the config lives on `/mnt/c`). With the default theme nothing runs. It also re-syncs when nvim opens and when focus returns. Custom path: `theme.terminal.config`.

**Sessions and Herdr**: `persistence.nvim` saves on exit and `core/autocmds/session.lua` also saves in the background every `session.autosave_ms` (only if something changed and without closing your auxiliary windows), so a power cut doesn't lose the state. Inside Herdr (`HERDR_ENV=1`) `utils/herdr.lua` registers nvim as an "agent" with the resume `nvim +HerdrResume` (a user command that restores the folder's session); on exit it releases it, so a normal `:q` doesn't reopen the pane. It doesn't override a real agent already occupying the pane. It is **off by default** (`session.herdr = false`): Herdr 0.9.x ignores the resume (needs >= 0.10.0) and nvim showed up in the Agents panel with no benefit. Enable: `session = { herdr = true }` in `local.lua`; `autosave_ms = 0` disables autosave.

**Inline agent** (`lua/agent/`, `<leader>a` menu, doc in `docs/cheatsheets/agent.md`): ONE-shot actions (implement, review, explain, ask, fix, document, refactor, hand off to Herdr) on the function under the cursor or the selection, with no chat or sidebar. One folder, one contract per piece: `backends/<cli>.lua` (`build`/`parser`; claude, opencode, **ollama**, **openai** (LM Studio/llama.cpp/vLLM) and `command` for CLIs declared in `agent.custom`), `actions/<action>.lua` (target, context, prompt, output), `context/` (treesitter target + budgeted providers: rules, **types** the target uses (treesitter + LSP, any language), LSP signatures, diagnostics with their line, outline), `output/<kind>.lua` (presenters: `replace` = inline diff with accept/reject, `findings` = diagnostics, `text` = window with streaming), `ui/` (spinner, preview, window, picker). Adding a backend/action/presenter/provider = one file + its `NAMES` list; the menu comes from the action registry. `protocol.lua` keeps the output format demanded of the model TOGETHER with its parser. Settings in `settings.agent`; the backend+model chosen with `<leader>am` are saved in `stdpath("state")/agent.json`. **Local models and setup** (`backends/{http,ollama,openai,command}.lua`, `setup/`): `setup/detect.lua` measures CLIs, servers (incl. the Windows host from WSL) and GPU/RAM in parallel without touching anything; `recommend.lua` (pure) proposes models by VRAM; `actions.lua` is the only thing that modifies (start `ollama serve`, `/api/pull`, remember `endpoints`, set backend/model); open it with `<leader>am` → Setup or `scripts/agent-setup.sh`. Ollama sizes `num_ctx` per request (otherwise it truncates silently) and `light_backend` leaves docs/explain on a local model without moving the main one. Everything loads lazily (the `agent` facade only on first use; lualine looks at `package.loaded`). Measured pitfalls: `claude -p` by default drags ~46k input tokens, with `--setting-sources "" --tools "" --system-prompt` ~600 (**don't use `--bare`**: it disables the OAuth login); the CLIs run in `stdpath("cache")/agent` (without the repo's AGENTS.md); opencode falls back to the default agent (with tools) if it can't find the requested one, **opencode latency** (measured, `opencode-go/deepseek-v4.1-flash`, one-line task): cold `opencode run` ~7-9 s and ~20k input tokens because the global MCP servers' schemas ride along (`agent.opencode.mcp=false` disables them by name, ~5 s and ~830 tokens); a private `opencode serve` + HTTP `POST /session/:id/message` (`backends/opencode_server.lua`, session created ahead, basic-auth password) is ~2 s; `run --attach` (v1.19) emits no text, so it is not used; `vim.system{cwd=}` does not update `$PWD` and opencode resolves its project from it, so `runner.lua` sets `PWD` (otherwise the repo's AGENTS.md/CLAUDE.md, ~10k tokens, leaked into every prompt); `opencode run` hangs waiting on an inherited stdin when called by hand without `</dev/null`; and its route could not be tested with network in the development environment (parser and command were, with synthetic events and `scripts/test-agent.sh`). `.agent.md` at the project root adds conventions to every prompt. **DDD** (`lua/agent/ddd/`, `<leader>aD` menu, a separate feature): local static analysis of layers, imports, naming and aggregates (port/implementation/wiring/use cases) that costs 0 tokens (`diagnose`: diagnostics, quickfix and panel), and LLM actions (`implement`, `review`, `missing`, `ask`) with their own registry (`ddd/actions`) that reuse the same pipeline and receive the `<ddd>` section (provider `context/providers/ddd.lua`). Only what is inside layer directories is read; settings in `agent.ddd`. **Hexagonal architecture levels**: one folder and one menu per level — `agent/ddd/` (`<leader>aD`), `agent/repository/` (`<leader>aP`: port, implement, review, check), `agent/service/` (`<leader>aS`: implement, review, deps) —, each with its own action registry (same contract and pipeline as `agent/actions`) and a local 0-token analysis; what is shared (rg, type reading) lives in `agent/discovery.lua`; `<leader>a` is left for generic things. **Tests** (`agent/tests/`, `<leader>aT`: write/mock/fix + local gaps) and **lenses** (`agent/lenses/`, `<leader>aL`: security/performance/concurrency/errors/api, they come out as diagnostics with their origin) are two more levels with their own registry and menu. The pipeline recognizes action hooks: `retarget` (the result goes to ANOTHER file; the target becomes the end of the test file and the original is the `subject` the context comes from, with `job.view` so the spinner shows on the tested code), `merge` (the model returns only what is new, `protocol.APPEND_RULES`), `reveal` (opens the destination to the side) and `prepare` (prior work WITHOUT a model, e.g. running the test: if it passes, 0 tokens); lenses use `gate` (words: with none, they don't call the model). The findings of a lens only replace those with the same `source`. Adding a level = folder + registry + `menus/agent_<level>.lua` + line in `menus/init.lua`. **Adapters** (`agent/repository/contracts/`, providers `contracts` and `schema`, Repository-level actions in `<leader>aP` (port, implement, review, check)): if the target is an adapter (e.g. `PostgresOrderRepository`) the following are injected, with their path: the port it implements (by name or `implements`/`impl X for`/`var _ X`, searched with rg), the missing methods, the entity the port names, a sibling implementation as a style example and the real table (SQL/Prisma migrations) with dialect/driver/parameters; silent if the code is not an adapter; scope `type` = the type under the cursor or its receiver's. **Persistent findings** (`agent/persist.lua` + `core/autocmds/agent.lua`): those from `review`/`ddd review`/`ddd diagnose` are saved in `stdpath("state")/agent-findings.json` with their line's text and restored (re-anchored) when the file is opened; `fix` and `ddd fix` read them via the `findings` provider and, on accept, the resolved ones are removed. `<leader>ax` stop does NOT delete them; they are cleared one at a time with `<leader>ac` clear (cursor line or selection), with `<leader>aC` (file) or with `:AgentClear [file|all]`. Two models per backend (tiers `main`/`light`; docs and explain go to the light one, `<leader>am` → Light model); `i`/`d`/`f` open the inline instruction field (empty Enter = no instruction), `a`/`R` require it. Short menu: i d r e a f R g(handoff, Herdr only) h(history) m x l (plus c/C clear). **Two-level fix**: `f` = inline (target = the lines of the diagnostic under the cursor, scope `diagnostic` in `context/target.lua`; it carries `<around>` and, via the LSP's `typeDefinition` on the diagnostic's identifiers, the types they point to) and `F` = block (the whole function, same types). `runs/` saves every run in `stdpath("state")/agent-history.jsonl` (prompt, response, tokens, cost, what you did with it) and `<leader>ah` shows it with a spend report; `claude -p` runs with `DISABLE_PROMPT_CACHING=1` (the cache only charged writes: -40 % per call). The colors in `agent/ui/highlights.lua` are derived from the theme palette (no linking to Diff*/Comment) and recomputed on `User NvThemeReload`.

**Start screen** (`lua/ui/start/`, buttons in `ui/dashboard.lua`): replaces NvChad's nvdash with the landing page's start screen: braille art (aqua), repo and branch (yellow), user (faint), then buttons of a fixed width, one soft block each (label left, shortcut right), the selected one solid blue; j/k, arrows or Tab move, Enter or a click activates, and each button's own shortcut (`ff fo fw th ch ca rs`) jumps straight to it. `layout.lua` is pure (tested in `scripts/test-flat.sh`) and responsive: a short window drops the gaps between buttons, then the art. `init.lua` owns the buffer (filetype `nvdash`, which the rest of the config already recognizes), hides the cursor while it is shown and redraws on resize and when the art changes. To add a button, add it to `actions()` in `ui/dashboard.lua`.

**Flat design** (`lua/ui/flat/`, `settings.ui`): the whole editor looks like the landing page's demo editor, view by view. The editor itself is painted `deep` (the demo's editor; the theme's own bg is the "page" around it): `init.lua` applies the groups and then `groups.rebase` moves EVERY group base46 or a plugin painted with the theme bg onto `deep` (also `fg = bg`, how themes hide characters), so gutters, panels and plugin windows follow. A float, menu or panel is a FILLED BLOCK (`soft`), never a box: `winborder = "solid"` adds one blank cell of padding and `FloatBorder` is painted like the block, so the "border" is air. Where the demo has 2-8px gaps or paddings the terminal uses half cells: `▀`/`▄`/`▐` in `FlatEdge` (block over editor). Selection is solid blue with `on` text, matches and keys are yellow, groups purple, hints faint, additions/deletions are veils (blended over `deep`). `palette.lua` derives the tokens (bg, deep, soft, fg, dim, faint, on, accents) from the active base46 theme (or the terminal-inherited one), `groups.lua` turns them into highlight groups (pure, tested by `scripts/test-flat.sh`), `init.lua` re-applies on `ColorScheme`, `NvThemeReload` and every `LazyLoad` and owns the global options (`winborder`, `fillchars`, `showtabline = 0`, blinking cursor). The views: `telescope.lua` is telescope's `create_layout` (results over the prompt, preview right, titles INSIDE the blocks in faint capitals, the previewed path in yellow as the preview's winbar, the hit line veiled only when the entry has a line; `geometry` is pure); `whichkey.lua` replaces which-key's `view.show` (a full-width soft panel over the statusline, 4 columns filled by ROWS, groups first, faint `Space » +Find … Esc close · BS back` footer; `grid` is pure) and `labels.lua` hides the words the open menu already says (the demo ports it as `trimLabel`); `grug.lua` (soft panel, `Grug FAR · g? help` header, each input a `deep` bar with its aqua label); `chips.lua` (harpoon's chosen row as a chip as wide as its text); `notify.lua` (the demo's note: bottom right, a row of air above and below the text so the thin level bar runs the block's whole height (half-cell rows cannot carry it), the lead phrase bold in the level color, fades in, one row of editor between notes and above the statusline, stacks above Neovim's own message window); Neovim's messages use the built-in message UI (`vim._core.ui2`, `settings.ui.messages`): no "Press ENTER" screen; short ones (`"file" written`, errors, warnings, a `print`) are routed into the notes by wrapping its `msg_show` (`notify.message`: kind → color, progress steps coalesced into one note, a repeated note refreshes instead of stacking), listings/long output/prompts stay in its own windows styled as blocks, `g<` for the full pager; `motion.lua` (fade-in of which-key (plus a 2-row slide), modals, harpoon and notes, ~110ms ease-out; every frame flushes its own redraw because which-key waits for keys in a loop that does not redraw, an animation yields as soon as someone else moves its window, and full-screen surfaces (telescope, commit panel) never fade: blending them repaints the whole terminal; `settings.ui.motion = false` turns it off); `fresh.lua` (yank and agent accepts glow yellow and fade); `keys.lua` (the demo's keycaps, off by default, `:FlatKeys`). Elsewhere: modals (`utils/modal.lua`: title in fg capitals, tree glyphs, input as a `deep` bar), the start screen buttons (row + `▀` edge), the lualine theme (`ui/lualine/theme.lua`: soft bar, mode/position chips of fixed width), diagnostics blocks (`message  source  1/N`, no icon or label: the bar and the veil say the severity; at the text column) and their line popup, blink (no blank rows, `label … detail`, docs half a cell apart), the terminal float (NvChad's `Alt+i`, `chadrc.term`: theme bg, the demo's place), Trouble (flat list, `Diagnostics N` header), Diffview (soft `Changes` panel, `HEAD`/`WORKING TREE` headers, no diagnostics in diffs) and the commit/agent panels (`commit/highlights.lua`, `agent/ui/highlights.lua`). Plugins take their `border` from `require("ui.flat").border()` (`"solid"`, `"float"` compact, `"beside"` for a block glued right of another; `"single"` with `ui.flat = false`). New surfaces must take their colors from `groups.lua`, never hardcode a color or a border style. The landing page's theme picker (`docs/index.html`) ports `palette.lua` to JS: keep both derivations in sync. To compare a view with the demo, capture nvim through a terminal emulator (pty + pyte → HTML) rather than tmux, which drops erased cells' colors.

**Per-machine settings**: `lua/local.lua` (git-ignored) returns a partial table that is merged over `core/settings.lua` (theme, disabled languages, format-on-save, vim options, clipboard, light mode...). Example: `return { languages = { disabled = { "astro" } } }`.

## Performance

- **git-blame** is off by default — toggle with `<leader>Gb` (no `BufRead` overhead)
- **Telescope** respects `.gitignore` in `find_files` (skip `node_modules`, `dist/`, etc.)
- **nvim-tree** hides git-ignored dirs by default — toggle with `I` or `git.ignore = false`
- Plugins are lazy-loaded via events, ft, cmd, or keys (not on startup)

- `ftdetect/yarnspinner.vim` — `*.yarn` → `yarnspinner` filetype
- `syntax/yarnspinner.vim` — syntax highlighting for YarnSpinner dialogue scripts

## Gotchas

- **Clipboard (WSL/SSH without DISPLAY)**: `core/clipboard.lua` uses OSC 52 to copy (Alacritty + herdr forward it); pasting from the system is Ctrl+Shift+V in the terminal
- **ysc (YarnSpinner linter)** is optional: it is enabled only if `ysc` is on the PATH (`dotnet tool install -g yarn-spinner`, requires `dotnet`)
- **`:checkhealth mason`** warns about missing ruby/gem/php/java/julia/composer/luarocks: it is informational only, no tool in the config needs them
- **Contextual leader menus** (`lua/menus/` + each language's `menu` field): each language has its own letter and only exists in buffers of that filetype (g Go, d Dart, r Rust, p Python, t TS/JS, m Markdown, s CSS, j Java, k Kotlin); `<leader>G` Git only inside a repo. To add a language: a new entry in the `langs` table. Don't define a mapping that is both an action and a prefix of others (e.g. `<leader>h` + `<leader>h1`): which-key resolves it after `timeoutlen` and closes the popup
- **Long comments** (global `<leader>C` menu, `utils/comments.lua`): detects with treesitter (nodes `comment`, `line_comment`, `block_comment`... whichever exist in the grammar) blocks and runs of consecutive lines that are alone on their line, of `comments.min_lines`+ lines, and `plugins/editing/ufo.lua` adds them to nvim-ufo's folds with `kind = "comment"` (it doesn't duplicate those the provider already folds). `Cc` folds and saves the "folded" preference (global, `stdpath("state")/comments.json`; `comments.auto_collapse` is only the initial value), `Ce` unfolds and turns it off, `Ct` toggles the one under the cursor without touching it. With the preference on, ufo closes the folds of `kind = "longcomment"` (its own kind: treesitter's uses the node name and would also close the short ones) when each buffer is first shown: `comments.sync_ufo` adds/removes that kind in the LIVE list `require("ufo.config").close_fold_kinds_for_ft.default`; a `BufWinEnter` aligns the buffers that already existed and folds NOW (`fold_now`: synchronous `:fold` + close, before the first redraw) the newly opened buffers, because ufo's provider is asynchronous and let the opened file show for a few tens of ms; ufo then rebuilds the folds and closes them by kind without it being noticeable. Comments at the end of a line of code don't count. The closed fold's text (`fold_text`) adds the first line with content if the first one is just `/**`
- **Conventional commits** (`lua/commit/`, `<leader>G` menu: `Gc` panel, `Gm` panel + AI draft, `GM` automatic commit without a panel, `Ga` amend): ONE panel (`commit/panel.lua`, three stacked floats: files, an `acwrite` message with filetype `gitcommit`, and an agent status line below, because `virt_lines_above` on row 0 doesn't get drawn) with the three entry points of `commit/init.lua`. One folder, one responsibility: `conventional.lua` (PURE: `split`, `parse_header`, `check` for the live indicator, `rewrite` of type/scope, `suggest_type/scopes`, `clean_message`), `git.lua` (status with +/− per file via `--numstat`, stage/unstage, async commit, branch/upstream), `ai.lua` (prompt + `describe`, which announces in the panel what will be sent BEFORE spending anything), `auto.lua` (`GM`: no panel and in the background), `highlights.lua` (derives from the `Agent*` ones, which come from the theme), `panel.lua` (UI). The AI goes through `require("agent").complete` (`agent/oneshot.lua`: same backend/model as the actions, light tier reassignable with `agent.tiers.commit`, returns `usage` as the callback's 3rd argument); the draft is never requested on its own (except `Gm`) and replaces the message in an undoable way. **The AI message ALWAYS comes out in English and on a single line** (Conventional header; there is no language setting). It is fast on purpose: COMPACT diff (`git.diff_for_ai`: no git headers, `-U1`, no lockfiles/maps/snapshots, `diff_max_chars` cap split among files), the branch and the types; subjects of previous commits are NOT sent (the model copied their language; the scope vocabulary is computed locally). Measured with haiku: ~2 s and ~$0.0004. `GM`: if there are staged files it commits only those; otherwise it stages everything modified except `git.commit.sensitive` (`.env`, keys...), asks for the message, validates the header and commits; if anything fails (no backend, AI, invalid header, hook) it undoes what it staged and warns. The types and limits live in `settings.git.commit` and the `.githooks/commit-msg` hook repeats the type list (shell): keep them identical. Pitfall: the close by `WinClosed` arrives queued; compare with the current panel before closing or it will close the next one you open. Tests: `scripts/test-commit.lua` (temp repo, fake backend, whole panel).
- **Code documentation** (`utils/docgen.lua`, `<leader>C` menu: `Cd` template, `Cm` missing): one entry per language in `LANGS` (where the comment goes and which lines) and, if "public" isn't "everything", in `PUBLIC`. - **Go: struct tags and snippets**: `utils/gotags.lua` is a blink.cmp source (`go` only) that derives the tag from the field NAME: in `SentAt time.Time ` + backtick it suggests `json:"sent_at"` (+ `,omitempty`, camelCase, yaml, db...); after `json:` or `json:"` it suggests the value and after `,` the options (`omitempty`, `omitzero`, `string`). Inside a tag the first item comes preselected (Enter accepts; outside it `preselect` stays off). With `gorm`: `gorm:"` suggests full values according to the field's name and TYPE (`primaryKey;type:text`, `type:text;not null`, `autoCreateTime`, `foreignKey:XID`...; no `not null` if it is a pointer) and after `;` single options (separator `;`, not `,`; textEdit from the last `;`); the backtick key menu also lists the gorm variants after json. `utils/gomodel.lua` (only `*_model.go` or `model.go`; gosmart calls it when starting a declaration and puts its items AT THE TOP of the list): `functable` → `func (XModel) TableName() string` (derived name: without `Model`, snake_case, plural), `funcdomain` (toDomain + fromDomain), `functodomain`, `funcfromdomain` (`func (m NoteModel) toDomain() *note.Note` / `fromDomain(n *note.Note) NoteModel`; domain `NoteModel`→`note.Note`; the constructor is looked up in the imported package and, if it isn't there, `Reconstitute` stays as a placeholder). With several structs: `functable X`, `from<Base>Domain`. Only for structs that don't have the function yet. For structs already written: `<leader>ga` (json snake_case), `<leader>gA` (+omitempty), `<leader>gD` (remove) via go.nvim/gomodifytags; also `<leader>gs` fill struct, `<leader>ge` if err, `<leader>gT` add test. Own snippets in `nvim/snippets/go.json` (VSCode format, blink reads them alongside friendly-snippets) with FULL NAMES, no acronyms, only for STATEMENTS and utilities (`iferr`, `errorsis`, `waitgroup`, `contexttimeout`, `testtable`, `httphandlerjson`...). `utils/goindex.lua` is the shared index (treesitter over text: interfaces, structs, methods, functions, constants per file, package and module; cached by mtime; the unsaved buffer replaces its file) for the 0-token helpers `goiferr` (`if err` with the function's returns; the menu opens by itself and Enter accepts it after `x, err := …`, `vim.g.goiferr_preselect=false` turns it off), `gomap` (mappers between `XResponse`/`XRequest`/`XModel`… and its counterpart in the module), `gowire` (the module's `NewX` constructors with arguments resolved by type/interface), `goenum` (IsValid/Parse/UnmarshalText/String), `goport` (interface from a struct's methods and `var _ I = (*T)(nil)`) and `gohttp` (handlers from a service; what changes per router —detection in go.mod, signature, route, query, body, response— lives in `gohttpfw.lua`), all called by gosmart (their items carry a `sortText` with `!` to go on top) and tested in `scripts/test-go-smart.lua`. `utils/goimpl.lua` (treesitter, 0 tokens; gosmart calls it): the methods a struct is missing to satisfy its interface — after `func (s *T) ` (automatic menu) and when starting a declaration —; the interface comes from `var _ I = (*T)(nil)`, from the constructor that returns it, from the name (`noteService` ~ `NoteService`; also local module packages via `go.mod`) or from what is already implemented; the body calls the dependency in the same shape (`return s.repo.FindByID(ctx, id)`) or leaves a zero-value `return`; `…all missing` uses `$N` (nvim only supports one `$0`). Tests: `scripts/test-go-impl.lua` (`scripts/test-go.sh`). `utils/gosmart.lua` (treesitter) is the contextual source: when STARTING a declaration (`func`, `type` or `New…` at column 0) it offers `func` variants (simple, `error`, `value`, `pointer`, `bool`, `result error`, `pointer error`, `ctx error`, `ctx result error`, `main`, `init`), methods of EACH struct in the file (pointer, `error`, value, `String`), `NewX(fields…)` for structs without a constructor and `type` variants (struct, struct constructor, generic, interface*, enum string/iota, defined, func, error, options); after `type Envelope ` → `struct`/`interface`/`func`; with the name of a package struct in VALUE position (`x := Env`, `return Env`, arguments) Enter inserts the literal ALREADY filled (Tab from value to value; in type position it doesn't apply); inside a literal `Envelope{ }` (struct of the same package) it opens the menu by itself on Enter and offers `fill all fields` + the missing fields with default values; inside `interface { }` → method signatures (`method error`, `method ctx result error`, embed...). Noise is silenced right there: no buffer words or the LSP's generic `func`/`type`, and statement snippets only show up inside functions (declaration ones, at package level).
