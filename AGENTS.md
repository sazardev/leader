# my-nvim-setup

Neovim + NvChad v2.5 config — not an application. No CI or build system; las únicas comprobaciones automáticas son `scripts/gen-cheatsheet.sh --check` y `scripts/test-agent.sh` (parsers y objetivo del agente, sin red).

## Repo structure

- `install.sh` / `install.ps1` — instalador de un solo paso (Linux/WSL/macOS · Windows): dependencias, Neovim ≥ 0.11, enlace de `nvim/`, hooks, plugins, Mason y parsers; `--lang a,b` deja solo esos lenguajes (escribe `languages.disabled` en `lua/local.lua`, sin pisar uno existente). Usa `scripts/install-mason.lua` y `scripts/install-treesitter.lua`. `VERSION` es la versión de la config (se sube con `chore(release)` + tag `vX.Y.Z`)
- `nvim/` — mirrors `%LOCALAPPDATA%\nvim` on Windows. Symlink it (o usa el instalador):

  ```powershell
  New-Item -ItemType Junction -Path "$env:LOCALAPPDATA\nvim" -Target "C:\path\to\my-nvim-setup\nvim"
  ```

- `.agents/skills/caveman*` — OpenCode skills (lockfile: `skills-lock.json`)
- `CHEATSHEET.md` — **GENERADO**, no se edita: todas las teclas (menús del leader, LSP, autocompletado, nvim-tree, globales) leídas de los keymaps reales por `scripts/gen-cheatsheet.sh`; el hook `.githooks/pre-commit` lo regenera si el commit toca `nvim/`. `scripts/gen-cheatsheet.sh --check` falla si está desactualizado. Es la ÚNICA fuente de teclas: no copies tablas de teclas a los docs
- `docs/cheatsheets/` — solo lo que NO se deriva del código (qué hace cada cosa, flujos, herramientas, trampas): `README.md` + una página por lenguaje (`go.md` es la más detallada). Al cambiar menús, snippets o herramientas de un lenguaje, actualiza su página; sin tablas de teclas (esas salen del código)
- `scripts/` — `gen-cheatsheet.sh` (+ `.lua`): generador del cheatsheet (nvim headless con la config real, ignora `local.lua` vía `NVIM_NO_LOCAL=1`)
- `scripts/test-agent.sh` (+ `test-agent.lua`, `test-agent-backends.lua`, `fake-llm.py`): pruebas del agente inline (protocolo, parsers, diff, objetivo, backends locales y setup contra servidores falsos de Ollama/OpenAI); sin red ni tokens
- `scripts/agent-setup.sh`: setup de backends y modelos locales desde la terminal (informe, `--start`, `--pull`, `--auto`, `--use`, `--json`)
- `.gitignore` — excludes `.claude/` (machine-specific Claude config)

## How it works

- Plugins auto-install via `lazy.nvim` on first open
- Activate the auto-reload hook once per clone: `git config core.hooksPath .githooks` (the hook picks the right data dir for Windows or Linux)
- LSP servers and tools (gopls, vtsls, stylua, prettier, eslint_d, dart, etc.) auto-install via `mason-tool-installer`
- No manual setup beyond the symlink (o `./install.sh`, que además deja plugins, herramientas y parsers ya instalados). Un plugin con `build` pesado que dependa de un lenguaje debe llevar `enabled` según `languages.disabled` (ver `plugins/languages/go.lua`), si no `--lang` instalaría sus herramientas igualmente
- **Auto-reload**: `.githooks/post-merge` creates a marker on `git pull`; `core/autocmds/reload.lua` detects it on `UIEnter` and runs `luafile $MYVIMRC` to reload config automatically

## Architecture

Un archivo = una responsabilidad. Entrada mínima en `nvim/init.lua`; todo lo demás es modular:

```
nvim/
├── init.lua                  # solo bootstrap (lazy + core)
└── lua/
    ├── core/                 # arranque: settings, light, lazy, options, clipboard, theme
    │   ├── settings.lua      #   TODOS los ajustes configurables (+ overrides locales)
    │   ├── keymaps/          #   cleanup (quita NvChad) · general
    │   └── autocmds/         #   reload · treesitter · ui
    ├── languages/            # 1 archivo por lenguaje: DECLARA treesitter, lsp, mason, formatters, linters, menú
    │   ├── init.lua          #   registro: agrega las declaraciones y las sirve a cada consumidor
    │   └── actions/          #   acciones de los menús (go, dart, typescript, python, rust, jvm...)
    ├── appearance/           # tema por defecto vs heredado de la terminal (Alacritty → base46)
    ├── themes/               # temas de usuario de base46 (terminal.lua se genera de la paleta)
    ├── servers/              # overrides por servidor LSP (servers/<nombre>.lua) + cargador
    ├── agent/                # agente inline (<leader>a): backends/ actions/ context/ output/ ui/ handoff/ (ver abajo)
    ├── menus/                # menús contextuales del leader (buffer-locales) + contexto Git
    ├── plugins/<grupo>/      # 1 spec de lazy por plugin: core lsp tools syntax languages navigation editing git ui
    ├── ui/                   # dashboard (+ arts/: catálogo de arte ASCII), highlights, lualine
    ├── utils/                # helpers puros: terminal, project, actions, git, log, telescope
    └── chadrc.lua            # solo compone: tema + dashboard + ui de NvChad
```

**Añadir un lenguaje**: crea `lua/languages/<nombre>.lua` (contrato en `languages/init.lua`) y agrégalo a `NAMES`. No hay que tocar mason, treesitter, conform, nvim-lint ni LSP: salen del registro. Overrides de un servidor: `lua/servers/<servidor>.lua`.

**Añadir un plugin**: un archivo en `lua/plugins/<grupo>/`. Grupos nuevos: agrégalos a `GROUPS` en `core/lazy.lua`.

**Añadir un arte al dashboard**: crea `lua/ui/arts/<nombre>.lua` (devuelve la lista de líneas; **solo arte de puntos braille**, U+2800–U+28FF, nada de ASCII/bloques). Se descubre solo: `ui/arts/init.lua` escanea la carpeta, sin lista que mantener. Se elige desde el botón "Change Art" (`ca`) del dashboard; la elección se guarda en `stdpath("state")/dashboard.json`. Valor inicial: `settings.dashboard.art`.

**Tema heredado de la terminal** (`<leader>S`): lee `alacritty.toml` (Linux, Windows o WSL en `/mnt/*/Users/*/AppData`), resuelve sus `import` y genera un tema de base46 (`lua/themes/terminal.lua`) con el fondo exacto de la terminal, grises interpolados y acentos con contraste mínimo (`theme.terminal.min_contrast`). Se recuerda entre sesiones (estado en `stdpath("state")/appearance.json` + marcador junto a la caché de base46) y se sigue EN VIVO: mientras el tema activo es el terminal, un sondeo (`theme.terminal.watch_ms`, 1000 ms; 0 = apagado) hace `stat` de los archivos de la config y recompila al detectar un cambio (inotify no sirve: en WSL la config está en `/mnt/c`). Con el tema por defecto no corre nada. También re-sincroniza al abrir nvim y al volver el foco. Ruta personalizada: `theme.terminal.config`.

**Sesiones y Herdr**: `persistence.nvim` guarda al salir y `core/autocmds/session.lua` guarda también en segundo plano cada `session.autosave_ms` (solo si algo cambió y sin cerrar tus ventanas auxiliares), para que un corte de luz no pierda el estado. Dentro de Herdr (`HERDR_ENV=1`) `utils/herdr.lua` registra nvim como "agente" con el resume `nvim +HerdrResume` (comando de usuario que restaura la sesión de la carpeta); al salir lo libera, así que un `:q` normal no reabre el pane. No pisa a un agente real que ya ocupe el pane. Está **apagado por defecto** (`session.herdr = false`): Herdr 0.9.x ignora el resume (necesita >= 0.10.0) y nvim aparecía en el panel Agents sin beneficio. Activar: `session = { herdr = true }` en `local.lua`; `autosave_ms = 0` desactiva el autoguardado.

**Agente inline** (`lua/agent/`, menú `<leader>a`, doc en `docs/cheatsheets/agent.md`): acciones de UN disparo (implementar, revisar, explicar, preguntar, arreglar, documentar, refactorizar, entregar a Herdr) sobre la función bajo el cursor o la selección, sin chat ni sidebar. Una carpeta, un contrato por pieza: `backends/<cli>.lua` (`build`/`parser`; claude, opencode, **ollama**, **openai** (LM Studio/llama.cpp/vLLM) y `command` para CLIs declarados en `agent.custom`), `actions/<accion>.lua` (objetivo, contexto, prompt, salida), `context/` (objetivo por treesitter + proveedores con presupuesto: reglas, **tipos** que usa el objetivo (treesitter + LSP, cualquier lenguaje), firmas del LSP, diagnósticos con su línea, esquema), `output/<kind>.lua` (presentadores: `replace` = diff en línea con aceptar/rechazar, `findings` = diagnósticos, `text` = ventana con streaming), `ui/` (spinner, vista previa, ventana, selector). Añadir backend/acción/presentador/proveedor = un archivo + su lista `NAMES`; el menú sale del registro de acciones. `protocol.lua` guarda el formato de salida que se le exige al modelo JUNTO a su parser. Ajustes en `settings.agent`; backend+modelo elegidos con `<leader>am` se guardan en `stdpath("state")/agent.json`. **Modelos locales y setup** (`backends/{http,ollama,openai,command}.lua`, `setup/`): `setup/detect.lua` mide en paralelo CLIs, servidores (incl. el host de Windows desde WSL) y GPU/RAM sin tocar nada; `recommend.lua` (pura) propone modelos por VRAM; `actions.lua` es lo único que modifica (arrancar `ollama serve`, `/api/pull`, recordar `endpoints`, fijar backend/modelo); abre con `<leader>am` → Setup o `scripts/agent-setup.sh`. Ollama dimensiona `num_ctx` por petición (si no, trunca en silencio) y `light_backend` deja docs/explain en un modelo local sin mover el principal. Todo se carga perezosamente (la fachada `agent` solo al primer uso; lualine mira `package.loaded`). Trampas medidas: `claude -p` por defecto arrastra ~46k tokens de entrada, con `--setting-sources "" --tools "" --system-prompt` ~600 (**no usar `--bare`**: desactiva el login OAuth); los CLIs corren en `stdpath("cache")/agent` (sin AGENTS.md del repo); opencode cae al agente por defecto (con herramientas) si no encuentra el pedido, y su ruta no se pudo probar con red en el entorno de desarrollo (parser y comando sí, con eventos sintéticos y `scripts/test-agent.sh`). `.agent.md` en la raíz del proyecto añade convenciones a todo prompt. **DDD** (`lua/agent/ddd/`, menú `<leader>aD`, función aparte): análisis estático local de capas, imports, nomenclatura y agregados (puerto/implementación/cableado/casos de uso) que cuesta 0 tokens (`diagnose`: diagnósticos, quickfix y panel), y acciones LLM (`implement`, `review`, `missing`, `ask`) con registro propio (`ddd/actions`) que reutilizan el mismo pipeline y reciben la sección `<ddd>` (proveedor `context/providers/ddd.lua`). Solo se lee lo que está dentro de directorios de capa; settings en `agent.ddd`. **Niveles de la arquitectura hexagonal**: una carpeta y un menú por nivel — `agent/ddd/` (`<leader>aD`), `agent/repository/` (`<leader>aP`: port, implement, review, check), `agent/service/` (`<leader>aS`: implement, review, deps) —, cada uno con su registro de acciones (mismo contrato y pipeline que `agent/actions`) y un análisis local de 0 tokens; lo compartido (rg, lectura de tipos) en `agent/discovery.lua`; `<leader>a` queda para lo genérico. **Pruebas** (`agent/tests/`, `<leader>aT`: write/mock/fix + gaps local) y **lentes** (`agent/lenses/`, `<leader>aL`: security/performance/concurrency/errors/api, salen como diagnósticos con su origen) son dos niveles más con su registro y su menú. El pipeline reconoce ganchos de acción: `retarget` (el resultado va a OTRO archivo; el objetivo pasa a ser el final del archivo de pruebas y lo original es el `subject` del que sale el contexto, con `job.view` para que el spinner se vea en el código probado), `merge` (el modelo devuelve solo lo nuevo, `protocol.APPEND_RULES`), `reveal` (abre el destino a un lado) y `prepare` (trabajo previo SIN modelo, p. ej. correr la prueba: si pasa, 0 tokens); las lentes usan `gate` (palabras: sin ninguna, no llaman al modelo). Los hallazgos de una lente solo reemplazan los del mismo `source`. Añadir un nivel = carpeta + registro + `menus/agent_<nivel>.lua` + línea en `menus/init.lua`. **Adaptadores** (`agent/repository/contracts/`, proveedores `contracts` y `schema`, acciones del nivel Repository en `<leader>aP` (port, implement, review, check)): si el objetivo es un adaptador (p. ej. `PostgresOrderRepository`) se inyectan, con su ruta, el puerto que implementa (por nombre o `implements`/`impl X for`/`var _ X`, buscado con rg), los métodos que faltan, la entidad que el puerto nombra, otra implementación hermana como ejemplo de estilo y la tabla real (migraciones SQL/Prisma) con dialecto/driver/parámetros; silenciosos si el código no es un adaptador; scope `type` = el tipo bajo el cursor o el de su receptor. **Hallazgos persistentes** (`agent/persist.lua` + `core/autocmds/agent.lua`): los de `review`/`ddd review`/`ddd diagnose` se guardan en `stdpath("state")/agent-findings.json` con el texto de su línea y se restauran (reubicados) al abrir el archivo; `fix` y `ddd fix` los leen vía el proveedor `findings` y, al aceptar, los resueltos se quitan. `<leader>ax` stop NO los borra; se limpian de uno en uno con `<leader>ac` clear (línea del cursor o selección), con `<leader>aC` (archivo) o con `:AgentClear [file|all]`. Dos modelos por backend (tiers `main`/`light`; docs y explain van al ligero, `<leader>am` → Light model); `i`/`d`/`f` abren el campo de instrucción en línea (Enter vacío = sin instrucción), `a`/`R` lo exigen. Menú corto: i d r e a f R g(handoff, solo Herdr) h(historial) m x l (más c/C clear). **Fix en dos niveles**: `f` = en línea (objetivo = las líneas del diagnóstico bajo el cursor, scope `diagnostic` en `context/target.lua`; lleva `<around>` y, vía `typeDefinition` del LSP sobre los identificadores del diagnóstico, los tipos a los que apunta) y `F` = bloque (la función entera, mismos tipos). `runs/` guarda cada ejecución en `stdpath("state")/agent-history.jsonl` (prompt, respuesta, tokens, coste, qué hiciste con ella) y `<leader>ah` lo muestra con informe de gasto; `claude -p` corre con `DISABLE_PROMPT_CACHING=1` (la caché solo cobraba escrituras: -40 % por llamada). Los colores de `agent/ui/highlights.lua` se derivan de la paleta del tema (nada de enlazar a Diff*/Comment) y se recalculan en `User NvThemeReload`.

**Ajustes por máquina**: `lua/local.lua` (ignorado por git) devuelve una tabla parcial que se mezcla sobre `core/settings.lua` (tema, lenguajes desactivados, format-on-save, opciones de vim, clipboard, modo ligero...). Ejemplo: `return { languages = { disabled = { "astro" } } }`.

## Performance

- **git-blame** is off by default — toggle with `<leader>Gb` (no `BufRead` overhead)
- **Telescope** respects `.gitignore` in `find_files` (skip `node_modules`, `dist/`, etc.)
- **nvim-tree** hides git-ignored dirs by default — toggle with `I` or `git.ignore = false`
- Plugins are lazy-loaded via events, ft, cmd, or keys (not on startup)

- `ftdetect/yarnspinner.vim` — `*.yarn` → `yarnspinner` filetype
- `syntax/yarnspinner.vim` — syntax highlighting for YarnSpinner dialogue scripts

## Gotchas

- **Clipboard (WSL/SSH sin DISPLAY)**: `core/clipboard.lua` usa OSC 52 para copiar (Alacritty + herdr lo reenvían); pegar desde el sistema es Ctrl+Shift+V en la terminal
- **ysc (YarnSpinner linter)** es opcional: se activa solo si `ysc` está en el PATH (`dotnet tool install -g yarn-spinner`, requiere `dotnet`)
- **`:checkhealth mason`** avisa de ruby/gem/php/java/julia/composer/luarocks ausentes: es solo informativo, ningún tool de la config los necesita
- **Menús contextuales del leader** (`lua/menus/` + campo `menu` de cada lenguaje): cada lenguaje tiene su letra y solo existe en buffers de ese filetype (g Go, d Dart, r Rust, p Python, t TS/JS, m Markdown, s CSS, j Java, k Kotlin); `<leader>G` Git solo dentro de un repo. Para añadir un lenguaje: nueva entrada en la tabla `langs`. No definas un mapeo que sea a la vez acción y prefijo de otros (p. ej. `<leader>h` + `<leader>h1`): which-key lo resuelve tras `timeoutlen` y cierra el popup
- **Comentarios largos** (menú global `<leader>C`, `utils/comments.lua`): detecta con treesitter (nodos `comment`, `line_comment`, `block_comment`... los que exista en la gramática) bloques y rachas de líneas seguidas que están solas en su línea, de `comments.min_lines`+ líneas, y `plugins/editing/ufo.lua` los añade a los folds de nvim-ufo con `kind = "comment"` (no duplica los que el proveedor ya pliega). `Cc` pliega y guarda la preferencia "plegados" (global, `stdpath("state")/comments.json`; `comments.auto_collapse` es solo el valor inicial), `Ce` despliega y la apaga, `Ct` alterna el del cursor sin tocarla. Con la preferencia encendida ufo cierra los folds de `kind = "longcomment"` (kind propio: el de treesitter usa el nombre del nodo y cerraría también los cortos) al mostrar cada buffer por primera vez: `comments.sync_ufo` pone/quita ese kind en la lista VIVA de `require("ufo.config").close_fold_kinds_for_ft.default`; un `BufWinEnter` alinea los buffers que ya existían y pliega YA (`fold_now`: `:fold` + cierre síncronos, antes del primer repintado) los buffers recién abiertos, porque el proveedor de ufo es asíncrono y dejaba ver el archivo abierto unas decenas de ms; ufo luego rehace los folds y los cierra por kind sin que se note. Los comentarios al final de una línea de código no cuentan. El texto del fold cerrado (`fold_text`) añade la primera línea con contenido si la primera es solo `/**`
- **Commits convencionales** (`lua/commit/`, menú `<leader>G`: `Gc` panel, `Gm` panel + borrador de IA, `GM` commit automático sin panel, `Ga` amend): UN panel (`commit/panel.lua`, tres flotantes apilados: archivos, mensaje `acwrite` con filetype `gitcommit`, y una línea de estado del agente debajo, porque `virt_lines_above` en la fila 0 no se pinta) con las tres entradas de `commit/init.lua`. Una carpeta, una responsabilidad: `conventional.lua` (PURO: `split`, `parse_header`, `check` para el indicador en vivo, `rewrite` de tipo/scope, `suggest_type/scopes`, `clean_message`), `git.lua` (status con +/− por archivo vía `--numstat`, stage/unstage, commit asíncrono, rama/upstream), `ai.lua` (prompt + `describe`, que anuncia en el panel lo que se enviará ANTES de gastar nada), `auto.lua` (`GM`: sin panel y en segundo plano), `highlights.lua` (deriva de los `Agent*`, que salen del tema), `panel.lua` (UI). La IA va por `require("agent").complete` (`agent/oneshot.lua`: mismo backend/modelo que las acciones, tier ligero reasignable con `agent.tiers.commit`, devuelve `usage` como 3er argumento del callback); el borrador nunca se pide solo (salvo `Gm`) y reemplaza el mensaje de forma deshacible. **El mensaje de la IA sale SIEMPRE en inglés y de una sola línea** (cabecera Conventional; no hay ajuste de idioma). Es rápido a propósito: diff COMPACTO (`git.diff_for_ai`: sin cabeceras de git, `-U1`, sin lockfiles/mapas/snapshots, tope `diff_max_chars` repartido entre archivos), la rama y los tipos; NO se envían asuntos de commits anteriores (el modelo copiaba su idioma; el vocabulario de scopes se calcula en local). Medido con haiku: ~2 s y ~$0.0004. `GM`: si hay archivos preparados commitea solo esos; si no, prepara todo lo modificado salvo `git.commit.sensitive` (`.env`, llaves...), pide el mensaje, valida la cabecera y commitea; si algo falla (sin backend, IA, cabecera inválida, hook) deshace lo que preparó y avisa. Los tipos y límites viven en `settings.git.commit` y el hook `.githooks/commit-msg` repite la lista de tipos (shell): mantenlas iguales. Trampa: el cierre por `WinClosed` llega encolado; compara con el panel actual antes de cerrar o cerrará el siguiente que abras. Pruebas: `scripts/test-commit.lua` (repo temporal, backend falso, panel entero).
- **Documentación de código** (`utils/docgen.lua`, menú `<leader>C`: `Cd` plantilla, `Cm` faltantes): una entrada por lenguaje en `LANGS` (dónde va el comentario y qué líneas) y, si "público" no es "todo", en `PUBLIC`. Reusa `utils/blocks.lua` (`blocks.list`: funciones/tipos sin closures). `export function`/`@decorador` se capturan envueltos: `decl_of` saca la declaración real. Snippets de etiquetas (`todo`, `fixme`...) en `snippets/all.json` con `${LINE_COMMENT}` (lo resuelve blink); `todo-comments` ya resalta esas etiquetas.
- **Sesiones** (`persistence.nvim`, `utils/session.lua`, menú global `<leader>P`): guarda buffers y ventanas al salir, una por carpeta (y por rama de git; `main`/`master` usan la base). NO se restauran solas: botón "Restore Session" (`rs`) del dashboard (solo si hay sesión para esa carpeta) o `<leader>Pr`; `<leader>Ps` elige proyecto, `<leader>Pl` la última, `<leader>Pw` guarda ya, `<leader>Px` no guarda al salir. Antes de guardar se cierran las ventanas auxiliares (árbol, terminal, outline). Abrir un solo archivo (`nvim x`) y salir sobrescribe la sesión de esa carpeta: usa `<leader>Px` si no quieres. Qué incluye: `options.sessionoptions` en `core/settings.lua`. El deshacer persistente (`undofile`) ya lo activa NvChad
- **Autoread** (`core/autocmds/autoread.lua`): `autoread` + `checktime` en `FocusGained`/`TermClose`/`TermLeave` recargan lo que cambian git o los formatters fuera de nvim (nunca pisa buffers con cambios sin guardar). Búsqueda con `ignorecase`+`smartcase` e `inccommand=split` (vista previa de `:s`) en `options`
- **git-conflict.nvim**: sin mapeos por defecto (`co`/`cb` pisarían operadores `c`); las acciones viven en el menú `<leader>G` (o ours, T theirs, B both, N none, n/p siguiente/anterior, l lista en quickfix)
- **Go: tags de struct y snippets**: `utils/gotags.lua` es una fuente de blink.cmp (solo `go`) que deriva el tag del NOMBRE del campo: en `SentAt time.Time ` + backtick sugiere `json:"sent_at"` (+ `,omitempty`, camelCase, yaml, db...); tras `json:` o `json:"` sugiere el valor y tras `,` las opciones (`omitempty`, `omitzero`, `string`). Dentro de un tag el primer ítem viene preseleccionado (Enter acepta; fuera de ahí `preselect` sigue apagado). Con `gorm`: `gorm:"` sugiere valores completos según nombre y TIPO del campo (`primaryKey;type:text`, `type:text;not null`, `autoCreateTime`, `foreignKey:XID`...; sin `not null` si es puntero) y tras `;` opciones sueltas (separador `;`, no `,`; textEdit desde el último `;`); el menú de claves del backtick también lista las variantes gorm tras json. `utils/gomodel.lua` (solo `*_model.go` o `model.go`; lo llama gosmart al empezar una declaración y pone sus ítems AL PRINCIPIO de la lista): `functable` → `func (XModel) TableName() string` (nombre derivado: sin `Model`, snake_case, plural), `funcdomain` (toDomain + fromDomain), `functodomain`, `funcfromdomain` (`func (m NoteModel) toDomain() *note.Note` / `fromDomain(n *note.Note) NoteModel`; dominio `NoteModel`→`note.Note`; el constructor se busca en el paquete importado y, si no está, `Reconstitute` queda como placeholder). Con varios structs: `functable X`, `from<Base>Domain`. Solo para structs que aún no tienen la función. Para structs ya escritos: `<leader>ga` (json snake_case), `<leader>gA` (+omitempty), `<leader>gD` (quitar) vía go.nvim/gomodifytags; también `<leader>gs` fill struct, `<leader>ge` if err, `<leader>gT` add test. Snippets propios en `nvim/snippets/go.json` (formato VSCode, los lee blink junto a friendly-snippets) con NOMBRES COMPLETOS, sin siglas, solo de SENTENCIAS y utilidades (`iferr`, `errorsis`, `waitgroup`, `contexttimeout`, `testtable`, `httphandlerjson`...). `utils/goindex.lua` es el índice compartido (treesitter sobre texto: interfaces, structs, métodos, funciones, constantes por archivo, paquete y módulo; caché por mtime; el buffer sin guardar sustituye a su archivo) de las ayudas 0-tokens `goiferr` (`if err` con los retornos de la función; el menú se abre solo y Enter lo acepta tras `x, err := …`, `vim.g.goiferr_preselect=false` lo apaga), `gomap` (mapeadores entre `XResponse`/`XRequest`/`XModel`… y su par del módulo), `gowire` (constructores `NewX` del módulo con argumentos resueltos por tipo/interfaz), `goenum` (IsValid/Parse/UnmarshalText/String), `goport` (interfaz desde los métodos de un struct y `var _ I = (*T)(nil)`) y `gohttp` (handlers desde un servicio; framework por go.mod), todas llamadas por gosmart (sus ítems llevan `sortText` con `!` para ir encima) y probadas en `scripts/test-go-smart.lua`. `utils/goimpl.lua` (treesitter, 0 tokens; lo llama gosmart): los métodos que le faltan a un struct para cumplir su interfaz — tras `func (s *T) ` (menú automático) y al empezar una declaración —; la interfaz sale de `var _ I = (*T)(nil)`, del constructor que la devuelve, del nombre (`noteService` ~ `NoteService`; también paquetes locales del módulo vía `go.mod`) o de lo ya implementado; el cuerpo llama a la dependencia con la misma forma (`return s.repo.FindByID(ctx, id)`) o deja un `return` de ceros; `…all missing` usa `$N` (nvim solo admite un `$0`). Pruebas: `scripts/test-go-impl.lua` (`scripts/test-go.sh`). `utils/gosmart.lua` (treesitter) es la fuente contextual: al EMPEZAR una declaración (`func`, `type` o `New…` en columna 0) ofrece variantes de `func` (simple, `error`, `value`, `pointer`, `bool`, `result error`, `pointer error`, `ctx error`, `ctx result error`, `main`, `init`), métodos de CADA struct del archivo (puntero, `error`, valor, `String`), `NewX(campos…)` para los structs sin constructor y variantes de `type` (struct, struct constructor, generic, interface*, enum string/iota, defined, func, error, options); tras `type Envelope ` → `struct`/`interface`/`func`; con el nombre de un struct del paquete en posición de VALOR (`x := Env`, `return Env`, argumentos) Enter inserta el literal YA relleno (Tab de valor en valor; en posición de tipo no aplica); dentro de un literal `Envelope{ }` (struct del mismo paquete) abre el menú solo al pulsar Enter y ofrece `fill all fields` + los campos que faltan con valores por defecto; dentro de `interface { }` → firmas de método (`method error`, `method ctx result error`, embed...). Ahí mismo se silencia el ruido: sin palabras del buffer ni el `func`/`type` genérico del LSP, y los snippets de sentencia solo salen dentro de funciones (los de declaración, a nivel de paquete).
- **Convención de `desc` en keymaps**: 2+ palabras y la PRIMERA es la sección (`"Harpoon add file"`, `"Go run"`, `"General save"`). El botón Mappings del dashboard (`NvCheatsheet`) y `CHEATSHEET.md` agrupan por esa palabra y descartan los desc de una sola (el generador avisa). Los menús del leader lo cumplen solos (`menus.desc` antepone la 1ª palabra del nombre del menú). Las teclas nativas de Neovim se excluyen midiendo `nvim --clean`; los grupos nativos que aún cuelan en NvCheatsheet van en `excluded_groups` (`ui/dashboard.lua`)
- **blink.cmp: Tab/Esc/jk** (`plugins/editing/blink.lua`, `utils/blinkkeys.lua`, `core/keymaps/general.lua`): con el menú abierto `Tab`/`S-Tab` eligen sugerencia; sin menú, dentro de un snippet saltan de hueco. `Esc` y `jk` con el menú abierto SOLO lo cierran (`cancel`: deshace el auto_insert, vuelve a lo tecleado) y mantienen insert + snippet; sin menú salen de insert. Flujo para conservar lo tecleado en un hueco: `Esc` y luego `Tab`. No pongas el salto de snippet ANTES de `select_next` en `<Tab>`: impide elegir sugerencias dentro de un snippet
- **Treesitter** compila parsers con el compilador de C del sistema (`gcc`) y requiere el binario `tree-sitter` (`tree-sitter-cli`)
- **No standalone run**: this is a config repo, must be symlinked to Neovim's config path
- **lazy-lock.json** committed for reproducible plugin versions
- `.claude/settings.local.json` is NOT committed (machine-specific permissions)
- **Astro formatting** requires `prettier-plugin-astro` in the project's `node_modules` or installed globally — Mason only installs `prettier` itself
- **mini.surround** keymaps: `sa` add, `sd` delete, `sr` replace surrounding delimiters
- **flash.nvim** keymaps: `s` jump to any word label, `S` jump to treesitter nodes (preserves native `r` replace char)
- **telescope-fzf-native** requires `cmake` installed on the system (auto-disabled if missing via `enabled`)
- **Auto-reload limitation**: `luafile $MYVIMRC` reloads Lua config but does NOT install/remove plugins or treesitter parsers. For plugin changes, use `:Lazy sync` or restart nvim.
- **Light mode** (`nvim/lua/core/light.lua`): auto-detects RAM ≤ 2GB and disables all resident stuff — LSP servers, go.nvim, golangci-lint (falls back to `go vet`). Mason installs only `goimports`+`gofumpt`. Keeps treesitter + conform (ephemeral formatters) + nvim-lint. Override with `NVIM_LIGHT=1|0` env, `settings.light.force` or `vim.g.light_mode`.
