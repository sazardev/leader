  opinions
  
It has a point of view.

  
A framework earns its keep by deciding things for you. These are the decisions, and the reasons.

  

    
speed
Lazy, or it doesn't ship
defaults.lazy = true. Plugins wait for an event, a filetype, a command or a key. Bytecode cache, unused built-ins off. Nothing runs that you didn't ask for.

    
modular
Declared, never wired
A language is one file declaring its parsers, LSP, formatter, linter and menu. Add a file and a name — mason, treesitter, conform and lint pick it up. One file, one responsibility.

    
frugal
Decide before you spend
Gates skip code that doesn't match a lens. The test action runs the test first. Static analysis is free. A model is called only when nothing local can answer.

    
keyboard
Every action has a key
Menus live under <Space>, one letter per context, and only exist where they apply. The cheatsheet is generated from the real keymaps, so it can't lie.

    
pinned
Reproducible by default
Plugins install at the commits in lazy-lock.json. Install on a new machine, get the same editor. Updating is a decision, not an accident.

    
light
Small machines are first-class
At ≤ 2 GB of RAM it turns off the resident processes (LSP, golangci-lint) by itself. NVIM_LIGHT=1|0 forces it either way.

  


  
What it refuses to be

  
    
    
  • A tab barbuffers and harpoon do the job, and a bar costs a column and a redraw.
    • 
    
  • An embedded chatthe agent does one shot on the function under your cursor and shows a diff. No sidebar.
    • 
    
  • A heavy session managerone session per folder and branch, autosaved. That's all.
    • 
    
  • A pile of plugins54 locked entries, counting the ones NvChad drags in. If it can be 60 lines of Lua, it is.
    • 
    
  • Someone else's colorsit can inherit your terminal's palette live, polling the Alacritty config.
    • 
    
  • A wall of optionsevery knob is in one file with its default and a comment; yours go in a git-ignored local.lua.
    • 
  







  custom, for speed
  
Go completion that reads your code.

  
Not snippets — completion built from your own interfaces, structs, constants and go.mod. Treesitter, no language model, 0 tokens, instant.

  

  

  
Plus struct tags derived from the field name, constructors, filled struct literals, sentinel errors and statement snippets. Seven helpers sit on one shared index (utils/goindex.lua); each is a module you can read in a sitting.







  ai, without the chat
  
An agent that respects your tokens.

  
One shot on the function or selection under the cursor, shown as an inline diff you accept or reject with one key. Claude Code, OpenCode, Ollama, LM Studio, llama.cpp… detected and configured for you. The call is trimmed to 579 input tokens instead of ~46,000.

  extend
  
    Add a thing, add a file.
    
  
    No wiring, no editing three registries. Each piece talks to a small contract, so you can replace one without touching its neighbors.
    
  
    

    nvim/lua/
  languages/       rust.lua          a language: LSP, formatter, menu
  plugins/editing/ flash.lua         a plugin, lazy by default
  agent/
    actions/         review.lua        a one-shot action
    lenses/          security.lua      a focused review
    tests/           convention.lua    where tests live per language
    backends/        ollama.lua        a model backend
  commit/         conventional.lua  pure validation, git, panel
  utils/          goenum.lua        a Go completion helper
  ui/arts/        fox.lua           a braille dashboard art
    
    
    
      
    The principles repeat everywhere:
    
      
      
        
    • One responsibility per module.Pure logic apart from what touches git, the LSP or the UI.
      • 
        
    • Open for extension.Discovered registries; new pieces don't edit old ones.
      • 
        
    • Depend on small contracts.build/parser for a backend, collect for context.
      • 
        
    • Every knob in one place.core/settings.lua, overridden by local.lua.

  install
  
    One command. All of it.
    
  
    Dependencies, Neovim ≥ 0.11 (no sudo), the link, git hooks, plugins at their pinned versions, LSPs, formatters, linters, treesitter parsers and the AI agent — then it tells you how long each step took. Re-running it brings everything up to date in seconds.
    
  
    
    $ curl -fsSL https://raw.githubusercontent.com/sazardev/my-nvim-setup/master/install.sh | bash
    
  
    
  
    
    
    optioneffect
    
    
    --lang go,luaonly those languages; the rest are disabled and never installed
    
    
    --theme catppuccinthe default theme
    
    
    --light | --no-lightforce light mode (no resident LSP) or turn it off; otherwise detected by RAM
    
    
    --agent autothe AI agent: the best backend found (default), a specific claude/haiku, or none
    
    
    --ask · --no-deps · --dry-runprompt before system changes · skip system packages · print the plan only
    
  
    
  
    Pass options after bash -s --: … | bash -s -- --lang go,lua --theme gruvbox. Windows: irm …/install.ps1 | iex (written, not yet tested on real Windows). Prefer a clone? git clone it and run ./install.sh.
