# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

Neovim + NvChad v2.5 config (not an application). No build, tests or CI. **`AGENTS.md` is the detailed reference** (architecture, gotchas, per-feature behaviour such as Go snippets, blink.cmp keys, sessions, terminal theme); read the relevant section before touching those areas. Docs, comments, user-facing text AND commit messages in this repo are written in English — match that.

## Commands

- Install on a fresh machine with ONE command: `curl -fsSL https://raw.githubusercontent.com/sazardev/my-nvim-setup/master/install.sh | bash` (piped, the script bootstraps: it fetches the repo into `~/.local/share/my-nvim-setup` and re-runs itself; it asks nothing, `--ask` prompts). From a clone: `./install.sh` (`--lang`, `--theme`, `--light/--no-light`, `--agent` (default `auto`), `--ask`, `--no-deps`, `--no-plugins`, `--dry-run`; Windows: `install.ps1` with the same options). Plugins install with `Lazy! restore` (pinned lockfile), never `sync`. The per-machine options (`--lang/--theme/--light`) are written to `nvim/lua/local.lua` by ONE implementation, `scripts/install-local.lua` (runs with `nvim -u NONE -l`; never overwrites an existing `local.lua`), shared by both installers. Config version lives in `VERSION` (release = `chore(release): vX.Y.Z` + git tag).
- Activate hooks once per clone: `git config core.hooksPath .githooks` (`pre-commit` regenerates `CHEATSHEET.md` when a commit touches `nvim/`; `post-merge` drops a marker so the config auto-reloads after `git pull`).
- All tests at once: `scripts/test.sh` (agent+commits, Go helpers, installer, cheatsheet check). Suites also run alone: `scripts/test-go.sh` (Go completion helpers), `scripts/test-install.sh` (installer settings).
- Agent and commit tests: `scripts/test-agent.sh` (protocol, backend parsers, diff, target, local backends + setup against fake Ollama/OpenAI servers in `scripts/fake-llm.py`, and the commit panel in `scripts/test-commit.lua` on a temp git repo; no network or tokens). Run it after touching `lua/agent/` or `lua/commit/`. `scripts/agent-setup.sh` is the terminal front-end of `lua/agent/setup/` (`--check`/`--start`/`--pull`/`--auto`/`--use`/`--json`). `test-agent.lua` is at Lua's 200-locals limit: put new suites in their own file.
- Regenerate cheatsheet: `scripts/gen-cheatsheet.sh`; verify it is current: `scripts/gen-cheatsheet.sh --check` (exit 1 if stale). It runs `nvim --headless` with the real config (`NVIM_NO_LOCAL=1 NVIM_LIGHT=0`), so nvim and the installed plugins are required.
- Try a change: `nvim` (config must be linked as the nvim config dir; `nvim/` is the config root) then `:luafile $MYVIMRC` to reload Lua. This does NOT install/remove plugins or treesitter parsers → `:Lazy sync` or restart.
- Lint Lua: stylua is the formatter (installed via Mason); lua_ls with lazydev gives API types.

## Landing page

`docs/index.html` is a hand-written static site: inline CSS/JS, no build, self-hosted Geist (`docs/fonts/`, SIL OFL license included), no external requests. Design rules: flat and square like the config (no borders, no radius, no shadows), palette = base46 gruvbox/gruvbox_light, very little content, smooth scroll reveals (respecting `prefers-reduced-motion`). Keep every number on it measured (startup ~20 ms) and update it when that changes. `docs/.nojekyll` lets GitHub Pages serve `docs/` as is.

## Generated files — don't hand-edit

- `CHEATSHEET.md` is generated from the real keymaps. Never edit it or copy key tables into docs. Every keymap `desc` must be 2+ words with the section as the FIRST word (`"Go run"`); single-word descs are dropped and the generator warns.
- `docs/cheatsheets/*.md` hold only what can't be derived from code (workflows, tools, pitfalls) — update the language's page when changing its menus, snippets or tools; no key tables.
- `lua/themes/terminal.lua` is generated from the terminal's `alacritty.toml`.
- `lua/local.lua` is git-ignored per-machine overrides, deep-merged over `core/settings.lua`; all configurable knobs belong in `core/settings.lua`.

## Architecture (big picture)

`nvim/init.lua` only bootstraps lazy + `core/`. Everything else is declarative and discovered, so adding things rarely means editing existing files:

- **Language registry** (`lua/languages/init.lua`): each `languages/<name>.lua` *declares* treesitter parsers, LSP servers, mason packages, conform formatters, nvim-lint linters and a leader `menu`. The registry aggregates them and serves each consumer (mason-tool-installer, treesitter, conform, nvim-lint, LSP, menus). New language = new file + add to `NAMES`; don't touch mason/treesitter/conform/lint/LSP specs. Contract is documented at the top of that file. Per-server overrides go in `lua/servers/<server>.lua`. Menu actions live in `languages/actions/`.
- **Plugins**: one lazy spec per file in `lua/plugins/<group>/`; new groups must be added to `GROUPS` in `core/lazy.lua`. Keep plugins lazy (event/ft/cmd/keys).
- **Leader menus** (`lua/menus/` + each language's `menu` field): buffer-local, only exist for that filetype (g Go, d Dart, r Rust, p Python, t TS/JS, m Markdown, s CSS, j Java, k Kotlin; `<leader>G` Git only inside a repo). Don't map a key that is both an action and a prefix of another (which-key closes the popup after `timeoutlen`).
- **Light mode** (`core/light.lua`): auto-enables at ≤2 GB RAM (or `NVIM_LIGHT=1|0`, `settings.light.force`, `vim.g.light_mode`) and disables resident things (LSP, go.nvim, golangci-lint). Any new language/plugin that runs a resident process must respect `require("core.light").enabled` (see `linters_light`, `mason.always`).
- **Dashboard art**: drop a braille-only (U+2800–U+28FF) file in `lua/ui/arts/`; auto-discovered.
- **Appearance/themes**: `appearance/` switches between default and a base46 theme derived live from the terminal config (polling, not inotify — WSL config lives on `/mnt/c`); user themes in `themes/`; `chadrc.lua` only composes.
- **Inline agent** (`lua/agent/`, `<leader>a`): one-shot actions over the function/selection, no chat UI. One folder, one contract per piece: `backends/` (CLI `build` + stream `parser`: claude, opencode), `actions/` (target scope, context providers, system/task prompts, output kind), `context/` (treesitter target + budgeted providers: rules, types (definitions of the types the target uses, language-agnostic via textobjects + LSP definition), diagnostics with their code line, callees, outline), `output/` (presenters: `replace` inline diff, `findings` diagnostics, `text` float), `ui/`, `handoff/` (Herdr). Besides claude/opencode there are `ollama` and `openai` (curl, local servers: `num_ctx` is sized per request because Ollama truncates silently) and `command` (CLIs declared in `settings.agent.custom`, e.g. Hermes Agent); `setup/` (detect → recommend → actions) wires them up and is the only code that starts/downloads/changes selection (always on explicit request); `light_backend` lets light-tier actions run on a different backend than the main one. Add a backend/action/presenter/provider = one file + its `NAMES` list; the leader menu is generated from the action registry. The model output format and its parser live together in `protocol.lua`. Never pass `--bare` to `claude -p` (breaks OAuth); keep `--setting-sources ""` (cuts ~46k input tokens). Actions have a model tier (`main`/`light`; docs and explain are light) and an inline instruction field (`input`, optional with `input_optional`). `agent/ddd/` is a separate feature (`<leader>aD`): local static analysis (layers by directory name, imports per language, naming profile, aggregate gaps; 0 tokens) plus LLM actions in their own registry (`ddd/actions`) that run through the same pipeline with a `<ddd>` context section; keep it independent of the normal actions. Any new agent UI module must call `require("agent.ui.highlights").ensure()` (the `Agent*` colors are derived from the theme there; not every path loads the `agent` facade, e.g. the DDD menu). Architecture levels each get a folder + own action registry + own `<leader>a<X>` menu (`ddd` aD, `repository` aP, `service` aS); shared helpers live in `agent/discovery.lua`; keep `<leader>a` for generic actions only. Tests (`agent/tests/`, `aT`) and lenses (`agent/lenses/`, `aL`) are two more levels: actions may declare pipeline hooks `retarget`/`merge`/`reveal`/`prepare` (result goes to another file, model returns only new code, pre-model work such as running the test) and lenses a `gate` so they skip (0 tokens) code outside their topic; findings from one lens replace only their own `source`. `agent/repository/contracts/` finds the port an adapter implements (rg + treesitter, any folder layout), its missing methods, a sibling implementation and the table schema (dialect-agnostic); providers `contracts`/`schema` must stay silent for non-adapters. Regexes built through Python edits must keep their `\\s`/`\\b` double backslashes. Review findings are persisted per file (`agent/persist.lua`, restored on `BufReadPost`, re-anchored by line text); `review` must never read earlier findings, `fix`/`ddd fix` must. Every run is logged by `runs/` (JSONL in the state dir: full prompt, response, tokens, cost and the user's decision) and shown by `<leader>ah`; `scripts/test-agent.sh` covers the store, report and detail. Keep the `<leader>a` menu short: one or two word descriptions, no accept/reject entries. Highlights are derived from the theme palette, never linked to Diff*/Comment. Details: `docs/cheatsheets/agent.md`.
- **Commits** (`lua/commit/`, `<leader>G` c/m/M/a): one panel (files staged vs not staged, message with live Conventional Commits validation, an agent status line announcing model + what it reads before spending anything). Pure logic in `conventional.lua`, git in `git.lua`, prompt in `ai.lua`, UI in `panel.lua`, the panel-less `GM` auto commit in `auto.lua`. AI messages are ALWAYS English, header line only (don't send past commit subjects: the model copies their language); types/limits in `settings.git.commit` (the `.githooks/commit-msg` hook repeats the type list). Details in `AGENTS.md`.
- **Go completion** is heavily custom: blink.cmp sources `utils/gotags.lua`, `utils/gomodel.lua`, `utils/gosmart.lua`, `utils/goimpl.lua` (missing interface methods as completion; `gohttp` keeps its router-specific part in `gohttpfw.lua`), `goiferr`/`gomap`/`gowire`/`goenum`/`goport`/`gohttp` (smart `if err`, layer mappers, constructor wiring, enum helpers, interface from struct, HTTP handlers; all on the shared `goindex.lua`; tests: `scripts/test-go.sh`) plus `nvim/snippets/go.json` (VSCode format, full-word names). See the Go gotcha in `AGENTS.md` before changing them.

## Environment notes

- Runs on Windows and WSL/Linux; hooks and clipboard (OSC 52) handle both. Treesitter needs `gcc` and `tree-sitter-cli`; telescope-fzf-native needs `cmake`.
- `lazy-lock.json` is committed; `.claude/` is git-ignored.
- Commit messages are written in English, in Conventional Commits style (`feat(session): …`, `fix(completion): …`), first line ≤ 72 chars.
