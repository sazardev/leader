# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

Neovim + NvChad v2.5 config (not an application). No build, tests or CI. **`AGENTS.md` is the detailed reference** (architecture, gotchas, per-feature behaviour such as Go snippets, blink.cmp keys, sessions, terminal theme); read the relevant section before touching those areas. Docs, comments, user-facing text AND commit messages in this repo are written in English — match that.

## Commands

- **Working on the app: `make`** (lists the targets; the Makefile follows the tasks picker's format, so `<leader>Rr` lists them too). `make dev` is the real-time loop (`scripts/dev-watch.sh`: runs Leader, rebuilds and restarts it when Rust changes, restarts it when Lua changes; polling, no extra tools; `PROFILE=fast` default = the `fast` Cargo profile, release speed rebuilt in seconds, `dev` = debug, `release`). Also `make run|open|restart|kill|build|timing|snap` (a PNG of the window: `make snap ARGS=file KEYS=" ff"`), `make test-gui` (the app's Lua suite alone, seconds), `make eval` (pass rates of the agent per action × model, `evals/README.md`; `MODELS=replay/golden,replay/noop` is free), `make test|check|lint|fmt` (`fmt` formats only the Lua files you changed), `make package|install|uninstall|icons|docs|cheatsheet|clean`.
- Install on a fresh machine with ONE command: `curl -fsSL https://raw.githubusercontent.com/sazardev/leader/master/install.sh | bash` (piped, the script bootstraps: it fetches the repo into `~/.local/share/leader` and re-runs itself; it asks nothing, `--ask` prompts). From a clone: `./install.sh` (`--lang`, `--theme`, `--light/--no-light`, `--agent` (default `auto`), `--ask`, `--no-deps`, `--no-plugins`, `--dry-run`; Windows: `install.ps1` with the same options). Plugins install with `Lazy! restore` (pinned lockfile), never `sync`. The per-machine options (`--lang/--theme/--light`) are written to `nvim/lua/local.lua` by ONE implementation, `scripts/install-local.lua` (runs with `nvim -u NONE -l`; never overwrites an existing `local.lua`), shared by both installers. Config version lives in `VERSION` (release = `chore(release): vX.Y.Z` + git tag; `CHANGELOG.md` gets the version's section from `<leader>GRc` (release kit) and a hand-written `### Highlights` at its top).
- Activate hooks once per clone: `git config core.hooksPath .githooks` (`pre-commit` regenerates `CHEATSHEET.md` when a commit touches `nvim/`; `post-merge` drops a marker so the config auto-reloads after `git pull`).
- All tests at once: `scripts/test.sh` (agent+commits, Go helpers, installer, flat design, settings panel, file operations, .gitignore helper, Go project setup, Flutter / Dart helpers, language packs, project documents kit, release kit, config loads cleanly, cheatsheet and web docs checks). Suites also run alone: `scripts/test-go.sh` (Go completion helpers), `scripts/test-install.sh` (installer settings), `scripts/test-flat.sh` (flat design tokens and groups), `scripts/test-prefs.sh` (settings panel), `scripts/test-files.sh` (file operations), `scripts/test-diagcopy.sh` (copy diagnostics), `scripts/test-history.sh` (undo steps, clipboard, yank history), `scripts/test-gitignore.sh` (.gitignore helper), `scripts/test-gosetup.sh` (Go project setup), `scripts/test-flutter.sh` (build_runner output, codegen watch, Dart completion), `scripts/test-langs.sh` (language packs: test adapters, setup presets, SQL runner, packs), `scripts/test-kit.sh` (project documents kit: presets, compose, snapshot, flows, build scopes, records, features, recipes), `scripts/test-release.sh` (release kit: changelog, checklist, PR request).
- Agent and commit tests: `scripts/test-agent.sh` (protocol, backend parsers, diff, target, local backends + setup against fake Ollama/OpenAI servers in `scripts/fake-llm.py`, and the commit panel in `scripts/test-commit.lua` on a temp git repo; no network or tokens). Run it after touching `lua/agent/` or `lua/commit/`. `scripts/agent-setup.sh` is the terminal front-end of `lua/agent/setup/` (`--check`/`--start`/`--pull`/`--auto`/`--use`/`--json`). `test-agent.lua` is at Lua's 200-locals limit: put new suites in their own file.
- Regenerate cheatsheet: `scripts/gen-cheatsheet.sh`; verify it is current: `scripts/gen-cheatsheet.sh --check` (exit 1 if stale). It runs `nvim --headless` with the real config (`NVIM_NO_LOCAL=1 NVIM_LIGHT=0`), so nvim and the installed plugins are required.
- Web documentation: `scripts/gen-docs.sh` renders README.md, CHEATSHEET.md, CHANGELOG.md, docs/cheatsheets/*.md and AGENTS.md into `docs/docs/index.html` (the site's `/docs/`); `--check` exits 1 if stale. It reads the Markdown from the git INDEX (what is being committed; `--worktree` for a preview), needs only nvim. The pre-commit hook regenerates it after the cheatsheet. Smoke test of the real config: `scripts/test-startup.sh` (a normal start + one file per language must raise no error).
- Try a change: `nvim` (config must be linked as the nvim config dir; `nvim/` is the config root) then `:luafile $MYVIMRC` to reload Lua. This does NOT install/remove plugins or treesitter parsers → `:Lazy sync` or restart.
- Lint Lua: stylua is the formatter (installed via Mason); lua_ls with lazydev gives API types.
- Desktop app (`app/`, Rust): `cargo build --release --manifest-path app/Cargo.toml -p leader-gui` → `app/target/release/leader`; install with `app/install.sh` (or `./install.sh --app`); tests `scripts/test-app.sh` (`--gui` opens the real window). Look at a change with `LEADER_SNAPSHOT=/tmp/x.png [LEADER_KEYS=" ff"] app/target/release/leader file` (PNG of the frame, then quits); `LEADER_TIMING=1` prints startup and input latency. Format with `cargo fmt` (app/rustfmt.toml), lint with `cargo clippy`.

## Landing page

The documentation lives in `docs/docs/` (generated, see below) with the landing's look (palette, Geist, flat) and is linked from its top bar and footer.
`docs/index.html` is a hand-written static site: inline CSS/JS, no build, self-hosted Geist (`docs/fonts/`, SIL OFL license included), no external requests. Design rules: flat and square like the config (no borders, no radius, no shadows), palette = base46 gruvbox/gruvbox_light, very little content, smooth scroll reveals (respecting `prefers-reduced-motion`). Keep every number on it measured (startup ~20 ms) and update it when that changes. `docs/.nojekyll` lets GitHub Pages serve `docs/` as is. The editor demo is a scripted mock of the real UI: statusline (mode, file, branch, agent spinner, E/W pills only when > 0, project, line:col), which-key menus and agent/commit panels must copy what the config shows (labels from the real keymap `desc`s), hover (`K`), signature help, the diagnostics line popup and the completion docs window must look like the real floats, and keycaps are transient chips so nothing can stick. The scenarios are grouped in tabs (Complete, Edit, Go, Find, Files, Inspect, Agent, Git, Workspace) and read one shared mini project (`PROJ`), so search, grep, replace and the tree always agree. Telescope, nvim-tree, the modals (`utils/modal.lua`), grug-far, harpoon, flash, git views and the dashboard are drawn flat as overlays. When a menu or panel changes, update its scenario. Which-key menus in the demo are generated from the REAL keymap descriptions (dump `nvim_get_keymap` in a Go buffer inside a git repo; menu labels = first word of the menu name + text, see `menus/init.lua`), never typed by hand. The theme picker (`t`) ports `appearance/terminal_theme.lua` + `color.lua` to JS: terminal palettes (bg, fg, ANSI 0-15) are turned into the page's CSS variables with the same rules (min contrast 3.0), so keep both derivations in sync.

**Wallpapers page** (`docs/wallpapers/`, hand-written like the landing, no generator): it reads `manifest.json` and the `thumbs/` (webp) next to it, both written by `node brand/publish.mjs`, picks the device from the visitor's screen (phone / desktop / ultrawide / 4K) and links each download to an asset of the GitHub release named in the manifest (`brand-N`, flat names `<device>-<design>.png`, plus one zip per device). `publish.mjs --release` creates that release; its tag points to an ORPHAN commit on purpose (`git describe --tags`, which the release kit uses, never sees it). The landing teases it with a panel (`#wallpapers`) and a nav link; its numbers come from the manifest, never typed by hand.

## Generated files — don't hand-edit

- `docs/docs/index.html` (the web docs) is generated from the Markdown by `scripts/gen-docs.lua` (a small renderer: headings, lists, tables, code, links between the docs become anchors). Never edit it: edit the .md files. New guide = a line in its `PAGES`.
- `CHEATSHEET.md` is generated from the real keymaps. Never edit it or copy key tables into docs. Every keymap `desc` must be 2+ words with the section as the FIRST word (`"Go run"`); single-word descs are dropped and the generator warns.
- `docs/cheatsheets/*.md` hold only what can't be derived from code (workflows, tools, pitfalls) — update the language's page when changing its menus, snippets or tools; no key tables.
- `lua/themes/terminal.lua` is generated from the terminal's `alacritty.toml`.
- `lua/local.lua` is git-ignored per-machine overrides, deep-merged over `core/settings.lua`; all configurable knobs belong in `core/settings.lua`.

## Architecture (big picture)

`nvim/init.lua` only bootstraps lazy + `core/`. Everything else is declarative and discovered, so adding things rarely means editing existing files:

- **Language registry** (`lua/languages/init.lua`): each `languages/<name>.lua` *declares* treesitter parsers, LSP servers, mason packages, conform formatters, nvim-lint linters and a leader `menu`. The registry aggregates them and serves each consumer (mason-tool-installer, treesitter, conform, nvim-lint, LSP, menus). New language = new file + add to `NAMES`; don't touch mason/treesitter/conform/lint/LSP specs. Contract is documented at the top of that file. Per-server overrides go in `lua/servers/<server>.lua`. Menu actions live in `languages/actions/`.
- **Language packs and their shared layer**: `languages/packs.lua` (pure data, ONE pack per line: install.sh reads it with sed before nvim exists) groups registry languages into packs (go dart typescript web python rust sql swift jvm infra yarnspinner) over an always-on base (lua markdown json yaml toml). The installer asks ONE thing in a terminal: a checklist of packs, those whose tools are on PATH checked (`--lang`/`--yes`/no terminal: no question; an existing local.lua: not asked again); `scripts/install-local.lua` expands packs (`--packs`, `--expand`), `<leader>Sp` → Languages toggles a pack (`languages.packs.<id>`, one key per pack because `tbl_deep_extend` merges lists by index; wins over `languages.disabled`, see `languages.disabled()`). Languages declare `formatter_options` (conform per-formatter opts: biome `require_cwd`, sql_formatter's dialect). Shared pieces every language menu reuses: `langtest/` (tests in the editor: adapters pytest, jsunit (vitest/jest/bun), cargo, swift = `tests(buf)` via treesitter + `command(ctx)` + `parse(out, ctx)`; marks/diagnostics/quickfix like darttest; keys m M A . T O), `langsetup/` (project setup presets like gosetup: `langs/<lang>.lua` + `presets/<lang>/<topic>/<variant>`, `#` or `//` headers, JSON/.nvmrc/.python-version/.swift-format get no comment; keys under S), `langdebug/` (debugpy, codelldb, lldb-dap, configured on first use; keys under D), `sqlrun/` (connections found from settings/.env/DATABASE_URL/SQLite files; statement under cursor split on `;` outside strings/comments/`$$`; risky statements ask; results in `sql://results`). nvim-lint skips linters that are not installed. Swift's LSP is only enabled when `sourcekit-lsp` is on PATH. Tests: `scripts/test-langs.sh` (adapters on real runner output, presets, SQL, packs).
- **Plugins**: one lazy spec per file in `lua/plugins/<group>/`; new groups must be added to `GROUPS` in `core/lazy.lua`. Keep plugins lazy (event/ft/cmd/keys).
- **Leader menus** (`lua/menus/` + each language's `menu` field): buffer-local, only exist for that filetype (g Go, d Dart, r Rust, p Python, t TS/JS, Q SQL, i Swift, m Markdown, s CSS, j Java, k Kotlin; `<leader>G` Git only inside a repo). Menu entries take an optional 4th element (modes) in buffer-local menus too (SQL's run in visual mode). Don't map a key that is both an action and a prefix of another (which-key closes the popup after `timeoutlen`).
- **Light mode** (`core/light.lua`): auto-enables at ≤2 GB RAM (or `NVIM_LIGHT=1|0`, `settings.light.force`, `vim.g.light_mode`) and disables resident things (LSP, go.nvim, golangci-lint). Any new language/plugin that runs a resident process must respect `require("core.light").enabled` (see `linters_light`, `mason.always`).
- **Flat design** (`lua/ui/flat/`, knobs in `settings.ui`): palette tokens → highlight groups (pure, `scripts/test-flat.sh`) → applied on theme changes and plugin loads. The editor is painted `deep` like the demo's (every group painted with the theme bg is rebased onto it); floats are filled blocks with invisible padding borders (`require("ui.flat").border()`), never boxes, and half cells (`FlatEdge`) stand in for the demo's small gaps. Each view copies its demo scenario: telescope layout, which-key panel, grug-far, harpoon chips, notifier, Neovim's messages without hit-enter (`settings.ui.messages`), motion (fade-in, `settings.ui.motion`; frames flush their own redraw, full-screen surfaces never fade). New UI must take colors from `groups.lua` (no hardcoded colors or border styles). Details in `AGENTS.md`.
- **Settings panel** (`lua/prefs/`, `<leader>Sp`): one flat list of the settings worth changing live; a group = a file in `prefs/items/` (+ `NAMES` in `prefs/init.lua`; item contract at its top). Choices apply at once when the setting is read where it is used (or through `apply`), are saved in `stdpath("state")/prefs.json` (`prefs/store.lua`) and win over `local.lua`; whatever is read once at startup is marked `restart`. Direct keys only for the few that earn them (`St` `Sf` `Sl` `SM` `Si` `Su`). Tests: `scripts/test-prefs.sh`.
- **File operations** (`lua/files/`, `<leader>F`, and `a`/`r`/`d` in the tree): new file/folder, rename, move, duplicate, delete, copy path, in the flat modals (`utils/modal.lua`) and the picker of the settings panel. One piece each: `paths.lua` (pure: what you type → paths, copy names), `ops.lua` (file system; never overwrites, returns `ok` or `nil, reason`; delete = move to a trash in `stdpath("state")`, `<leader>Fu` restores), `buffers.lua` (open buffers, LSP `willRenameFiles`/`didRenameFiles` and the tree follow a move), `target.lua` (the tree row under the cursor, else the current file), `location.lua` (the destination picture), `init.lua` (asks and chains). Never call `vim.fn.delete` on the user's files directly: go through `ops.trash`. Tests: `scripts/test-files.sh`.
- **Code search** (`lua/codesearch/`, `<leader>fs`): "where is X handled?" with 0 tokens. `index.lua` reads every named function/type with treesitter (`scopes.symbols`, the agent's `textobjects` queries, so any language with a parser works; slices of ~12 ms, refreshed per file by mtime+size, knobs in `settings.search`), `rank.lua` is pure (identifier words, light stemming, name > path > doc/signature, tests rank lower), `init.lua` is the Telescope picker (dynamic finder with an empty sorter: the ranking is ours). Lexical, not semantic: it finds what names, comments and paths say. Tests: `scripts/test-search.sh`.
- **Project tasks** (`lua/tasks/`, `<leader>R`): the targets of the project's Makefile in one Telescope picker, run in the integrated terminal; 0 tokens, nothing resident. Works ONLY with a Makefile (no file → every action says so and `<leader>Rc` offers a preset; no other runners on purpose). `make.lua` lists targets (`make -qp` for `.PHONY` and the default goal + the file's `## text` descriptions), `init.lua` caches/sorts and owns the flows, `exec.lua` runs (asks before typing into a task that is still running), `store.lua` remembers the last target per project. Makefile **presets** are plain files in `tasks/presets/<language>/<preset>.mk` (auto-discovered; first line `# description`, every target `## text`, a `help` target, tabs). Tests: `scripts/test-tasks.sh` (a real make reads every preset).
- **.gitignore** (`lua/gitignore/`, `<leader>Gi`): topics = plain files `presets/<name>.gitignore` (line 1 `# Title: what it ignores`, line 2 `# detect: …`), detected from marker files/extensions (`detect.lua`), merged by pure `compose.lua` (adds only what is missing, never twice, never removes), checklist in `utils/modal.checklist`; warns about already-tracked files the new rules match. 0 tokens. Never put rules people commit on purpose in a topic: `scripts/test-gitignore.sh` runs real `git check-ignore`.
- **Go project setup** (`lua/gosetup/`, `<leader>gS` in the Go menu): golangci-lint v2, Air, Dockerfile, .dockerignore, CI, lefthook, .editorconfig as plain presets `presets/<topic>/<variant>.<ext>` (`# description` + `# target: path`), `{{module}}/{{go}}/{{main}}/{{binary}}` filled from go.mod (`vars.lua`); never overwrites, offers to rename a misnamed `.golangcli.yml`. Menu contexts accept `groups = { S = "setup" }` for sub-prefix names. Tests: `scripts/test-gosetup.sh` (real golangci-lint v2/air/lefthook validate the presets when installed).
- **Editing history** (`lua/history/`, `<leader>u`): undo word by word in insert mode (fed `<C-g>u`, only with an empty typeahead or a replay turns it into `u`), undo/redo flash, `U`/`<C-y>` redo, `<C-z>` undo, built-in `:Undotree`, yank list with `[y`/`]y` after a paste, and `settings.clipboard.keep` (x/c/visual p don't overwrite the clipboard). Its keys are bound after `menus.setup()` (lazy's which-key `c` stub). Tests: `scripts/test-history.sh`.
- **Start screen** (`lua/ui/start/`, buttons in `ui/dashboard.lua`) is our own (NvChad's nvdash is off); pure `layout.lua` + buffer glue, same look as the landing page's. **Dashboard art**: drop a braille-only (U+2800–U+28FF) file in `lua/ui/arts/`; auto-discovered.
- **Appearance/themes**: `appearance/` switches between default and a base46 theme derived live from the terminal config (polling, not inotify — WSL config lives on `/mnt/c`); user themes in `themes/`; `chadrc.lua` only composes.
- **Inline agent** (`lua/agent/`, `<leader>a`): one-shot actions over the function/selection, no chat UI. One folder, one contract per piece: `backends/` (CLI `build` + stream `parser`: claude, opencode), `actions/` (target scope, context providers, system/task prompts, output kind), `context/` (treesitter target + budgeted providers: rules, types (definitions of the types the target uses, language-agnostic via textobjects + LSP definition), diagnostics with their code line, callees, outline), `output/` (presenters: `replace` inline diff, `findings` diagnostics, `text` float), `ui/`, `handoff/` (Herdr). Besides claude/opencode there are `ollama` and `openai` (curl, local servers: `num_ctx` is sized per request because Ollama truncates silently) and `command` (CLIs declared in `settings.agent.custom`, e.g. Hermes Agent); `setup/` (detect → recommend → actions) wires them up and is the only code that starts/downloads/changes selection (always on explicit request); `light_backend` lets light-tier actions run on a different backend than the main one. Add a backend/action/presenter/provider = one file + its `NAMES` list; the leader menu is generated from the action registry. The model output format and its parser live together in `protocol.lua`. Never pass `--bare` to `claude -p` (breaks OAuth); keep `--setting-sources ""` (cuts ~46k input tokens). Actions have a model tier (`main`/`light`; docs and explain are light) and an inline instruction field (`input`, optional with `input_optional`). `agent/ddd/` is a separate feature (`<leader>aD`): local static analysis (layers by directory name, imports per language, naming profile, aggregate gaps; 0 tokens) plus LLM actions in their own registry (`ddd/actions`) that run through the same pipeline with a `<ddd>` context section; keep it independent of the normal actions. Any new agent UI module must call `require("agent.ui.highlights").ensure()` (the `Agent*` colors are derived from the theme there; not every path loads the `agent` facade, e.g. the DDD menu). Architecture levels each get a folder + own action registry + own `<leader>a<X>` menu (`ddd` aD, `repository` aP, `service` aU); shared helpers live in `agent/discovery.lua`; keep `<leader>a` for generic actions only. The everyday menu stays short (ask, docs, review, explain, fix, refactor…): what works on many pieces at once (`fixall`, `errors`, `errors_run`, `plan` and the proposal queue) is flagged `advanced = true` on the action and lives in `<leader>aA` (`menus/agent_advanced.lua`, keys of the queue in `batch/queue.lua`); each menu has its own key space. Tests (`agent/tests/`, `aT`) and lenses (`agent/lenses/`, `aL`) are two more levels: actions may declare pipeline hooks `retarget`/`merge`/`reveal`/`prepare` (result goes to another file, model returns only new code or, for `docs`, only the comment (`docplace.lua`), pre-model work such as running the test) and lenses a `gate` so they skip (0 tokens) code outside their topic; findings from one lens replace only their own `source`. `agent/repository/contracts/` finds the port an adapter implements (rg + treesitter, any folder layout), its missing methods, a sibling implementation and the table schema (dialect-agnostic); providers `contracts`/`schema` must stay silent for non-adapters. Regexes built through Python edits must keep their `\\s`/`\\b` double backslashes. Review findings are persisted per file (`agent/persist.lua`, restored on `BufReadPost`, re-anchored by line text); `review` must never read earlier findings, `fix`/`ddd fix` must. Every run is logged by `runs/` (JSONL in the state dir: full prompt, response, tokens, cost and the user's decision) and shown by `<leader>ah`; `scripts/test-agent.sh` covers the store, report and detail. Keep the `<leader>a` menu short: one or two word descriptions, no accept/reject entries. Highlights are derived from the theme palette, never linked to Diff*/Comment. Details: `docs/cheatsheets/agent.md`.
  **Agentic layer on top of the pipeline** (each piece one folder/file, wired through contracts, never by editing the flow it hangs from): `events.lua` (pub/sub: `proposal.accepting|accepted|dropped`, `job.settled`), `guards/` (checks before a request; `budget` is the first, pure core in `budget.lua`), `pipeline.launch(spec)` (a job on a target already known; `run` resolves the target then calls it; actions with `standalone = true` skip the target and own their `handler`), `verify/` (LSP regressions after accepting, optional build on save, one bounded retry), `refine.lua` (Tab on a proposal or an answer), `batch/` (N proposals in a row with one confirmation + the proposal queue `]`/`[`/`Y`/`Q`), `fixall/` (diagnostics grouped by function), `errors/` (tool output → errorformat → pieces), `review/` (staged diff: free checks + one numbered request), `plan/` (multi-file plans: locate → plan call → editable panel → chained steps), providers `callers`, `gitlog` and `edits` (`edits.lua` follows what you changed as hunks; the `next` action, `<leader>an`, is on demand and asks nothing when nothing changed), `context/init.lua` `arrange` (stable → volatile prompt order by `provider.stability`, for prefix-caching servers), `cache/` (answers to identical requests come back from disk, 0 tokens: `text`/`findings` only, looked up before the guards, never shared with tests). Derived actions (`verify_fix`, `plan_step`, `errors_fix`, refine) are built, not registered. One-shot calls are recorded in the history (`runs.call`). Tests: `test-agent-flow|batch|review|plan.lua` on the shared kit `scripts/agent-kit.lua` (fake backend, temp project, canned modal answers, no LSP).
- **Project documents** (`lua/agent/kit/`, `<leader>aS`): AGENTS.md, STACK.md, DESIGN.md, SPEC.md at the repo root, always with the sections in `compose.DOCS` (presets are tested against them). Presets are plain Markdown discovered from `presets/design/`, `presets/stack/<category>/` and `presets/principles/` (header `<!-- name: … -->` `<!-- desc: … -->` `<!-- core: true -->`); principles are appended to STACK.md as `## Engineering principles` by pure `compose.lua`, never written by the model. **Add-ons** (`presets/addons/<group>/`, `<!-- for: tags -->` matched against `presets.tags` = words of the stack's Summary/Stack) are merged by `compose.merge` (a row replaces the row with the same first word, other lines added once; idempotent, tested on every stack × add-on); groups and one-of groups are `presets.AXES`, shown with `modal.checklist` groups/`exclusive`. Package manager is not a file: `compose.use_package_manager` rewrites a pnpm preset to bun/npm (scripts `npm run`, binaries `npx`). `snapshot.lua` gathers the project's facts, `template.lua` is the 0-token AGENTS.md, `prompts.lua` the model requests (main tier, `kit_*`), `draft.lua` the page for free text.
